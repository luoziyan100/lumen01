# Done Notes: Search Intent Regression Guard

Status: IMPLEMENTED
Date: 2026-05-03
Implementer: Codex implementation window

## Summary

已修复“搜索上周/今天 AI 论文”被 planner/direct_answer/local_research 吞掉的问题。明确外部搜索请求现在会被 deterministic guard 强制转成 `academic_search`，不会再让普通聊天模型回答“我不能实时搜索”。

## normalizePlan

- feed mode 不再强依赖 `queries.length > 0`。
- 当 planner 给出 `recent_ai_feed` / `arxiv_category_feed` 但漏填 query 时，会补默认 query：`arXiv category feed`。
- `shouldSearch` 逻辑改为：`raw.shouldSearch && (queries.length > 0 || isFeedMode)`。

## enrich / deterministic guard

新增并导出：

- `looksLikeExternalSearchRequest(text)`
- `deterministicExternalSearchPlan(input, base?)`

行为：

- “搜索/找/检索 + 论文/文献/paper”强制进入外部搜索。
- “今天/上周/最近/最新 + AI/LLM/机器学习/arXiv + 论文”强制进入 `recent_ai_feed` 或 `arxiv_category_feed`。
- “今天”会映射到 `fromDate=currentDate` 且 `untilDate=currentDate`。
- “昨天”会映射到前一天单日范围。
- `plan.searchMode` 不再提前阻断 deterministic fallback。

## runtime guard

`runResearchHarness()` 在 planner 后增加 `tool_runtime_guard` trace step：

- 如果没有命中已有 ResultSet 引用，但用户文本是明确外部搜索请求，会再次调用 `deterministicExternalSearchPlan()` 修正 plan。
- 这样即使 planner 输出 `answer` / `local_research` / 空 query，也不会进入 direct answer。
- Result Set Memory 优先级保留：`R1 前 5 篇`、`刚才那 10 篇`、`它们的链接` 仍先走 resolver，不会被搜索 guard 覆盖。
