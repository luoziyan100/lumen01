## Architecture summary

- `loop.ts` is the only Research Agent runtime path.
- The loop calls the configured adapter with `RESEARCH_TOOLS`, appends assistant/tool result messages to history, and repeats until the assistant returns text.
- Tool results are serialized into `AgentMessage { role: "tool_result" }`, so conversation history is the state.
- `ResearchPage` persists the full `agentHistory` as hidden `research_notes` with role `agent_history`; visible UI still shows only user/assistant text.

`loop.ts` line count: 96 lines.

## Acceptance scenarios

The A-E scenarios are covered by `npm run test:agent-loop` with scripted adapters so they are repeatable.

### Scenario A - Basic search

Input:

```text
用户：搜索最新的LLM论文
```

Observed:

- Adapter chose `academic_search`.
- Loop appended a `tool_result`.
- Final assistant reply returned a paper-list response.

Test: `scenario A searches papers through academic_search and returns a list` passed.

Dev server search channel also responded on `http://127.0.0.1:5174/api/search-papers?...` with `total: 4`, confirming the Vite search API path is reachable.

### Scenario B - Reference resolution

Complete tested conversation:

```text
用户：搜索最新的LLM论文
工具结果：5 篇搜索结果，Paper 1 到 Paper 5
AI：推荐这5篇：Paper 1, Paper 2, Paper 3, Paper 4, Paper 5
用户：那你把这5篇做一个研究报告吧
AI 工具调用：read_papers({ papers: [Paper 1, Paper 2, Paper 3, Paper 4, Paper 5] })
工具结果：每篇返回 abstract_only evidence
AI：# 研究报告
```

Observed:

- The loop passed prior `tool_result` history into the next model call.
- The scripted model selected the five prior papers from conversation history.
- The final reply did not contain `没有可用于深度研究的搜索结果`.

Test: `scenario B uses conversation history to read the five previously recommended papers` passed.

### Scenario C - Continuous dialogue

Input:


Test: `scenario C reads the third paper from prior context` passed.

Test: `scenario D ordinary chat returns directly without tools` passed.
