## Persistence / Compatibility

- `ResearchPage` 现在恢复最近 10 个 `search_results` artifacts，而不是只读最新 1 个。
- 新 artifact 保存 `{ resultSet, results, plan, traceId, createdAt }`，保留旧 `results` 字段兼容。
- 旧 artifact 兼容：
  - 旧数组格式 `SearchResult[]`
  - 旧对象格式 `{ results, plan }`
  - 新对象格式 `{ resultSet }`
- SQLite 与 browser/dev `localStorage` fallback 共享同一 artifact 数据结构，因为都走 `services/research.ts` 的 `addResearchArtifact/listResearchArtifacts`。
- UI header 增加当前 storage mode：`SQLite` 或 `localStorage`。

## Runtime Guard

`deep_research` 已改成：

1. 先用 `resolveResultSetReference()` 解析已有结果集引用。
2. 如果命中已有结果集，禁止重新搜索。
3. 只有用户明确说“重新搜 / 再搜 / 换一批 / 重新查”等，或无法解析到结果集时，才允许 `runSearchPipeline()`。

同时新增确定性 resolver 支持：

- `刚才 / 上一轮 / 上面 / 你筛出来的 / 这些 / 它们`
- `前 5 篇 / 前五篇`
- `第 1-5 篇 / 第 1 到 5 篇`
- `R1 / R1-1 / R1-1 到 R1-5`
- `链接 / PDF / DOI / arXiv / 来源` 请求直接从保存的 result set 输出，不重新搜索。

补充实现：resolver 已前置到 planner 之前。

- runtime 进入 planner 前会先调用 `resolveResultSetReference()`。
- 如果是链接/DOI/PDF/来源类请求，命中 result set 后直接 deterministic answer，不需要 planner/API。
- 如果是研究/预览类请求，已解析目标会写入 `context.resolvedResultSetReference`，planner 只判断 intent，并被 runtime 强制 `target=resolved_result_set_items`、`shouldSearch=false`。

## Planner / Response

- Planner prompt 已加入“已有结果集引用不得搜索，除非显式重新搜索”的规则。
- Planner context 现在包含 recent result sets 摘要和稳定编号，例如 `R1-1`。
- 新搜索回复会在开头标明已保存的结果集，例如 `结果集 R1`，并提示后续可用 `R1 前 5 篇` 或 `R1-1 的链接` 引用。
- 搜索回复还会输出稳定编号清单，例如 `R1-1. Title`。
