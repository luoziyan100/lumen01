## 实现摘要

- 搜索结果现在会作为结构化 `searchResults` 从 agent runtime 返回，并由 `ResearchPage` 保存为 `lastSearchResults`，用于后续“第 N 篇 / 这篇 / 它”的引用解析。
- `AgentInputContext` 增加 `lastSearchResults`，planner prompt 只接收裁剪后的索引、标题、作者、日期、DOI、链接、开放 PDF 状态和摘要片段，避免把完整摘要无限塞进 planner。
- planner intent 已扩展：
  - `paper_detail`
  - `paper_preview`
  - `deep_research`
  - `import_to_library`
  - 保留原有 `academic_search / local_research / answer / feedback / clarify`
- 新增 paper reference 解析：
  - 支持 `第 2 篇`、中文数字、DOI、标题、source URL。
  - `这篇 / 那篇 / 它` 只有在最近搜索结果唯一时才自动解析，否则返回澄清问题。
- `paper_detail` 已实现：
  - 不下载 PDF。
  - 基于最近搜索结果中的 metadata/abstract 回答作者、年份、DOI、期刊、摘要、PDF 链接等问题。
  - 输出 prompt 要求明确“证据来源：metadata / abstract”，不能说读了全文。
- `paper_preview` 已实现：
  - 针对开放 PDF 做临时读取。
  - 默认不导入文献库。
  - PDF 下载失败或没有开放 PDF 时降级到 metadata/abstract，并在回答中说明证据层级。
  - 最终回答使用 `local_paper_analysis` 级别模型。
- 临时缓存已实现：
  - Tauri 端新增 `fetch_open_pdf`，使用应用 cache dir 下的 `paper-preview/pdf`，TTL 7 天，单文件限制 50MB。
  - 前端新增 `services/paper-preview.ts`，用 pdfjs 抽取预览文本，并把文本片段放入 localStorage 临时缓存，TTL 7 天，LRU 裁剪。
  - Vite dev fallback 新增 `/api/paper-preview/pdf`，解决浏览器开发模式下 PDF CORS 问题。
- `import_to_library` 已做显式边界：
  - 能识别用户导入/保存意图。
  - 本阶段不自动永久保存，回复会说明安全边界和当前未接入一键导入。
- `deep_research` 已做边界降级：
  - 不自动下载多篇并导入。
  - 引导用户先指定单篇或两篇做 preview。

## 未完全验证 / 风险

- 没有做真实外网 PDF 全链路验收，避免把具体出版社、arXiv、Semantic Scholar PDF 的网络/CORS/限速问题混入本轮代码验证。
- `paper_detail` 本阶段主要复用最近搜索结果 metadata/abstract，没有额外按 DOI 做二次 detail enrichment。
- 前端文本缓存使用 localStorage，适合 preview 片段，不是完整 PDF/text 数据库。Tauri 端已有 PDF 临时文件缓存，后续可把 text cache 迁到 app cache dir 或 IndexedDB。
- `import_to_library` 目前只识别并阻止自动导入，尚未实现安全的一键导入文献库流程。
