## P0: 裸 pronoun 不再直接绑定 ResultSet

修改位置：

- `src/agent/tools.ts`
- `src/agent/reference-resolver.ts`

改动：

- 新增 `hasStrongResultSetAnchor(text)`。
- 新增 `hasWeakPronounOnly(text)`。
- `resolveResultSetReference()` 现在只有强锚点才返回 result set。

仍会绑定 result set 的强锚点：

- `R1`、`R1-1`、`R1 前 5 篇`
- `第 1 篇`、`第 1-5 篇`
- `前 5 篇`
- `刚才那 10 篇论文`
- `你刚才筛出来的论文`

不再直接绑定 result set 的裸指代：

- `这些`
- `它们`
- `他们`
- `那几个`
- `这几个`

这些弱指代会先放行给 planner；只有在“链接/DOI/PDF/source 请求 + 最近 assistant 文本里确实有 R1-1 这类稳定编号”时，`resolveUserQuestion()` 才会从最近输出中恢复对应 result set refs。

## P1: “它”不再拦截普通对话

修改位置：

- `src/agent/reference-resolver.ts`

改动：

- `它` 不再天然等于论文。
- 只有满足以下条件之一，才进入 paper resolver：
  - 有 `currentPaper`
  - 当前文本有论文语义：`论文 / paper / DOI / arXiv / PDF / 摘要 / 方法 / 实验 / 结论`
  - 有强 result set anchor：`R1-1 / 第 N 篇 / 前 N 篇`

因此：

```text
它和 workflow 有什么区别？
```

在没有 `currentPaper` 时会保持原问题，放行 planner，不会提前 clarify 为“没有唯一论文对象”。

同时：

```text
这篇论文的结论是什么？
```

在有 `currentPaper` 时仍会绑定当前论文，并走 paper preview。

## P1: ContextPack 渲染 typed toolResults

修改位置：

- `src/agent/types.ts`
- `src/agent/context-pack.ts`
- `src/agent/runtime.ts`

新增 `ContextToolResult`：

```ts
type ContextToolResult =
  | { type: 'search_batches'; batches: SearchBatch[] }
  | { type: 'paper_detail'; text: string }
  | { type: 'paper_preview'; text: string; evidenceLevel: string }
  | { type: 'local_papers'; text: string }
  | { type: 'generic'; title: string; text: string }
```

`formatContextPackForModel()` 现在会渲染：

```text
## 工具执行结果 / 证据等级
### academic_search
#### arXiv ai recent feed
query: ...
mode: recent_ai_feed
date: ...
totalAvailable: ...
- 1. Title
  authors: ...
  DOI: ...
  source: ...
  PDF: ...
  abstract: ...

### paper_detail
...

### paper_preview
Evidence level: pdf_text_preview
...
```

Evidence section 现在也包含 DOI、source URL、PDF URL、cache 状态、warning 和 evidence text。删掉后续旧 prompt 时，ContextPack 已经包含基本可回答信息。

## P2: Planner 最近对话截断调整

修改位置：

- `src/agent/guides.ts`

改动：

- 新增 `buildPlannerRecentMessages(messages, { maxChars, perMessageMaxChars })`。
- 不再固定 `slice(-10)`。
- 默认按约 40k chars 总预算从最近消息向前收集，单条消息安全上限 2k chars。
- `compactRecentMessages()` 现在只是兼容 wrapper。

说明：

- 这仍是 planner prompt 的安全预算，不是全局 context compression。
- 全局 compression hook 仍只记录预算，不压缩结构化对象。

## 旧 Prompt 拼接是否保留

保留。

原因：

- 旧 `buildSynthesisUserPrompt()` / `buildEvidenceSynthesisUserPrompt()` 仍包含成熟的回答格式要求和降级规则。
- 本次先确保 ContextPack 自身承载 toolResults 和 evidence，不一次性删除旧 prompt，避免大面积行为回归。

后续删除计划：

1. 将旧 prompt 中的格式要求拆成 constraints。
2. 将搜索结果、paper detail、preview evidence 全部改由 ContextPack 提供。
3. 对比 eval 通过后，删除旧 prompt 的事实上下文部分，只保留输出格式约束。
