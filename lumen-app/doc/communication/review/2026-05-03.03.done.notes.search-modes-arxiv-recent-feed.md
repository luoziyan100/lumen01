## Search Modes

新增字段位于 agent/search 类型层：

```ts
type SearchMode =
  | 'keyword_search'
  | 'paper_lookup'
  | 'recent_ai_feed'
  | 'arxiv_category_feed'
```

Runtime 行为：

- `keyword_search`：继续走 OpenAlex + arXiv keyword + Semantic Scholar + Crossref。
- `recent_ai_feed`：只走 arXiv category feed，不再四源平均 limit。
- `arxiv_category_feed`：只走指定 arXiv categories。
- `paper_lookup`：本阶段先作为 plan/search option 保留，后续可继续强化 DOI/title 精确查询。

## arXiv Category Presets

当前 preset：

```ts
ai: ['cs.AI', 'cs.LG', 'cs.CL', 'cs.CV', 'cs.RO', 'stat.ML']
llm: ['cs.CL', 'cs.AI', 'cs.LG']
vision: ['cs.CV', 'eess.IV', 'cs.LG']
robotics: ['cs.RO', 'cs.AI', 'cs.LG']
```

用户显式输入 `cs.CL` / `cs.LG` / `cs.CV` 等分类时，走 `categoryPreset=custom` 和 `searchMode=arxiv_category_feed`。

## arXiv Feed Query

Rust 与 Vite 都使用：

```text
(cat:cs.AI OR cat:cs.LG OR ...)
AND submittedDate:[YYYYMMDD0000 TO YYYYMMDD2359]
sortBy=submittedDate
sortOrder=descending
```

分页：

- 每页最多 100。
- `feedLimit` 默认由 planner/fallback 传入；后端最大限制 200。
- 返回 `totalAvailable` 来自 `opensearch:totalResults`。
- 返回 `fetched` 是本次实际拉取并返回的结果数量。

## Limit Behavior

Feed 模式绕开旧逻辑：

```text
per_source = 4..15
```

`runAcademicSearches()` 对 feed 模式只执行一次搜索请求，limit 使用 `plan.feedLimit ?? 50`，不再把 limit 平均分给四个来源。

## Planner Recognition

Prompt 规则：

- “最近/本周/上周/某日期以来 AI 领域论文有哪些、一共有多少、arXiv 上有什么新论文” -> `recent_ai_feed`
- 指定 arXiv 分类 -> `arxiv_category_feed`
- “只推荐 N 篇最近 LLM 论文，不用详细分析” -> 仍允许 `keyword_search`

Deterministic fallback：

- 识别中文日期如 `4月27日以来`。
- 识别 `上周/最近/近期` 默认当前日期往前 7 天。
- 识别 `cs.CL` 等显式 arXiv category。
- 避免把“只推荐 10 篇最近 LLM 论文”强行改成 feed，除非用户问总数/feed/某日期以来。

## Answer Behavior

`buildSynthesisUserPrompt()` 现在会把 feed metadata 传给 synthesizer，并要求：

- 说明搜索模式。
- 说明分类。
- 说明日期区间。
- 说明 `totalAvailable` / arXiv totalResults。
- 说明本次 `fetched`。
- 不要把 fetched 当作总数。

## Review Notes

- Feed mode currently focuses on arXiv recall and total count. It does not enrich every feed item through OpenAlex/Semantic Scholar yet.
- `paper_lookup` is typed and normalized but not deeply specialized in this PR.
- arXiv feed max return is capped at 200 for safety; answers should use `totalAvailable` for total count and `fetched` for returned sample size.
- Existing Evidence Gate can still run PDF preview on selected feed results in later turns, but this PR primarily fixes recall/count for feed-style queries.
