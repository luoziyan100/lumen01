## Implementation summary

- Added provider id `openai-codex` with UI label `OpenAI GPT OAuth` and model hint `gpt-5.5`.
- Allowed `openai-codex` config to be saved with an empty API key field; the field is treated as an optional OpenClaw profile selector.
- Updated Settings so `openai-codex` uses a text input labeled `OpenClaw Profile（可选，不是 API Key）`, does not disable save when empty, and shows the OpenClaw login helper command.
- Fixed `chatWithAgentModel()` so role options apply to all providers, not only DeepSeek.
- Added Vite dev proxy support for `provider=openai-codex`.
- Server-side proxy reads OpenClaw auth profiles from `${OPENCLAW_STATE_DIR:-~/.openclaw}/agents/${LUMEN_OPENCLAW_AGENT_ID:-main}/agent/auth-profiles.json`.
- Empty profile selector now retries the next usable local `openai-codex` OAuth profile when the upstream response is `usage_limit_reached`; explicit selectors do not fallback.
- Codex Responses payload includes `instructions`, `stream: true`, `store: false`, and `reasoning: { effort: 'none' }`.
- Codex Responses payload intentionally omits `max_output_tokens`.
- SSE parser accumulates `response.output_text.delta` and falls back to `response.output_text.done`.
- Image inputs intentionally fail with a clear unsupported message for this local dev bridge.
- Tauri packaged mode intentionally fails with a clear unsupported message for `openai-codex`.

## Intentional limitations

- `openai-codex` is dev-server only; packaged Tauri mode is unsupported in this PR.
- Image inputs are not supported by the `openai-codex` dev proxy yet.
- The proxy does not implement OAuth login or token refresh UI.
- The proxy does not copy OpenClaw tokens into Lumen storage.
