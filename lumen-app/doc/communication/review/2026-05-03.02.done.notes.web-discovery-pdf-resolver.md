## Summary

- `previewSearchResultPaper()` 不再只看 `SearchResult.open_access_pdf_url`。

## Resolver Order

当前顺序：

1. Existing direct PDF URL
2. arXiv direct PDF from arXiv id/source URL/landing URL
3. Semantic Scholar detail by DOI or Semantic Scholar paper id
4. OpenAlex work detail by OpenAlex id / DOI / title search
5. Unpaywall by DOI
6. Crossref work links and landing page
7. Existing landing pages from `open_access_landing_url` / `source_url`
8. Web search provider: skipped in this stage

## Supported OA Sources

Implemented:

- Existing direct PDF
- arXiv PDF transform
- Semantic Scholar `openAccessPdf.url`
- OpenAlex `primary_location`, `best_oa_location`, `locations[]`
- Unpaywall `best_oa_location`, `oa_locations[]`
- Crossref `message.link[]`
- Landing page extraction for repository/publisher/author pages

Not implemented in this stage:

- Tavily / generic WebSearch provider.
- Browser automation discovery.

## Landing Page Extraction

`fetch_public_html` only fetches static text and does not execute JavaScript.

Extraction rules:

- `<meta name="citation_pdf_url" content="...">`
- `<meta name="dc.identifier" content="...">`
- `<meta property="og:url" content="...">`
- `<a href="...">` links containing `pdf`, `download`, `fulltext`, or `article-pdf`
- JSON-LD-ish `"contentUrl"`, `"url"`, `"downloadUrl"`
- OSF-style landing URL to `/download`
- arXiv `/abs/` to `/pdf/`

Every extracted candidate is converted to an absolute URL and then verified through the PDF fetch path.

## Blocklist

Blocklist is enforced in both:

- Tauri command layer: `fetch_open_pdf`, `fetch_public_html`
- Vite dev proxy: `/api/paper-preview/pdf`, `/api/paper-preview/html`

Patterns:

- `sci-hub`
- `libgen`
- `librarygenesis`
- `z-lib`
- `zlibrary`
- `annas-archive`

Blocked URLs are not opened, downloaded, or suggested as sources.

## PDF Verification

PDF verification still happens in the existing PDF fetch path:

- Tauri `fetch_open_pdf`
- Vite `/api/paper-preview/pdf`

Both require `%PDF` in the first 1024 response bytes. URL suffix or Content-Type alone is not trusted.

## User-Facing Downgrade Behavior

If no PDF is found, `PaperPreviewData.message` now includes a resolver attempt summary, for example:

```text
未找到可验证的公开开放 PDF，只能基于元信息和摘要回答。Resolver 尝试：...
```

This summary flows into `PaperEvidenceNote.warning`, so Evidence Gate and Deep Research answers can explain what was attempted.

## Review Notes

- This PR intentionally does not add a configurable WebSearch provider yet. It implements DOI/API/landing-page resolver first.
- `fetch_public_html` is named for the main use case but is also used to retrieve public JSON API text in the renderer resolver.
- Resolver may fetch some candidate PDFs twice only when bytes are not already available; verified resolver hits currently pass bytes through to avoid the common double-download path.
- All fetched PDFs remain temporary preview/cache material and are not imported into the user's library.
