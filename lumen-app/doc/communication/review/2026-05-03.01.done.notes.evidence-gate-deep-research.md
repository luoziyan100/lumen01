## Summary

已实现 `active/2026-05-03.01.active.brief.evidence-gate-deep-research.md` 的最小闭环版本：

- 新增 `EvidenceRequirement`：`metadata_ok` / `abstract_ok` / `single_pdf_required` / `multi_pdf_required`。
- Planner schema 和 prompt 已要求输出 `evidenceRequirement`、`targetPaperCount`。
- Runtime 加了 deterministic Evidence Gate 兜底；即使 planner 没稳定输出，遇到“方法、实验、结论、贡献、局限、定义、对比、综合、深读”等研究型请求也会进入 evidence pipeline。
- `academic_search` 在需要一手证据时会自动选择 topK 搜索结果，临时读取开放 PDF，构建 per-paper evidence notes，再综合回答。
- `deep_research` 不再硬编码降级；现在会解析当前论文/最近搜索结果/第 N 篇引用，或在有 query 时先搜索，再执行多篇临时 preview 和综合。
- 每篇 evidence note 都带 `evidenceLevel`：`pdf_text_preview` / `abstract_only` / `metadata_only`。
- ResearchPage 会持久化 `paper_preview` 和 `deep_research_report` artifacts。

## Evidence Gate Rules

`requiresPrimarySource(userText, plan)` 的规则：

- 明确搜索/推荐但用户说“只推荐、只列出、不用详细分析、不读全文”等，走 search-only。
- `plan.evidenceRequirement` 是 `single_pdf_required` 或 `multi_pdf_required` 时进入 evidence pipeline。
- `paper_preview` 和 `deep_research` 总是需要一手或降级证据。
- Planner 没给 evidence requirement 时，按关键词兜底：方法、实验、结果、结论、贡献、局限、理论、定义、证明、机制、对比、综合、综述、深读、详细分析等。

`requestedEvidencePaperCount(userText, plan)` 的规则：

- 优先使用 planner 的 `targetPaperCount`，范围 1-5。
- 其次解析“3篇/五篇”等显式数量。
- `single_pdf_required` 默认 1。
- 多篇、这些、它们、对比、综合、深读默认 3。

## Academic Search Evidence Pipeline

新流程：

```text
runAcademicSearches
-> reflectOnSearchResults
-> mergeSearchBatches
-> requiresPrimarySource
-> selectEvidencePapers(topK, direct PDF first)
-> previewSearchResultPaper for each
-> buildEvidenceSynthesisUserPrompt
-> synthesizeEvidenceAnswer
```

说明：

- topK 默认 3，最多 5。
- `selectEvidencePapers` 优先选择有 direct PDF 的结果；不足时补 metadata/abstract 结果。
- 没有 direct PDF 时 `previewSearchResultPaper` 自动降级为 `abstract_only` 或 `metadata_only`。
- 仍然只用临时 PDF/text 缓存，不导入文献库。

## Deep Research Pipeline

新流程：

```text
if plan.shouldSearch or no recent results but plan has queries:
  run academic search pipeline first

resolvePaperReferences:
  第 N 篇 / 第 1、2、3 篇 -> lastSearchResults
  paperReference -> existing resolver
  这几篇/这些/刚才 -> currentPaper + recent results
  fallback -> recent topK

previewEvidencePapers
-> synthesizeEvidenceAnswer(mode=deep_research)
-> deepResearchReport artifact
```

如果指定论文无法解析，会 clarify；不会再直接说“链路没接好”。

## Review Notes
