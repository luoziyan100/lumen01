## Summary

已把 Lumen 的研究 Agent 链路从“planner + runtime workflow”推进到 “ResolvedUserQuestion + Context Pack + Tool Manifest + Runtime Guard + State Writeback” 结构。当前实现保守落地架构骨架，并复用已有搜索、PDF preview、ResultSet memory 和 evidence gate。

## New Modules

新增模块：

- `src/agent/reference-resolver.ts`

  - 明确保留 `currentPaper`、`activeResultSet`、`recentSearchResultSets`、`resolvedQuestion` 等结构化对象。

## resolveUserQuestion Behavior

- 结果集引用：
  - `R1-1`、`R1 前 5 篇`、`第 1-5 篇`、`刚才那 10 篇` 会绑定到 `SearchResultSet` 和具体 `SearchResult[]`。
  - 输出 `standaloneQuestion`，例如“请基于结果集 R1 中的 R1-1...回答：...”

- 当前论文引用：
  - “这篇 / 它 / 该论文”优先指向 `currentPaper`。
  - 如果没有唯一 `currentPaper`，返回 `ambiguity`，runtime 进入 clarify。

- 重新搜索：
  - 如果用户明确说“重新搜 / 再搜 / 换一批”，resolver 不复用旧 ResultSet。

## Context Pack Format Example

`formatContextPackForModel()` 生成类似：

```text
## 用户原始输入
那前 5 篇做一个研究报告

## 指代消解后的本轮问题
请基于结果集 R1 中的 R1-1《...》、R1-2《...》回答：那前 5 篇做一个研究报告

## 本轮决策
intent: deep_research
target: resolved_result_set_items
evidenceRequirement: multi_pdf_required
shouldSearch: false

## 已解析对象
- R1-1: title / DOI / Source / PDF

## 工具 Manifest 边界
- academic_search: ...
- deep_research: ...

## 工具执行结果 / 证据等级
- Paper 1: Evidence: pdf_text_preview

## 约束
- 不要编造没有出现在搜索结果、PDF preview 或本地文献中的事实。
```

## Runtime Integration

`runResearchHarness()` 新增 trace steps：

- `resolve_user_question`
- `context_compression_budget`
- `build_context_pack`
- `tool_runtime_guard`

planner 现在接收：

- `resolvedQuestion`
- `resolvedResultSetReference`
- `recentSearchResultSets`
- typed `toolManifest`

synthesis prompts 现在会在原有任务 prompt 前附加 Context Pack 文档。

## Runtime Guard

- 外部搜索请求不能落入 direct answer 或 local research。
- ResultSet 引用优先级高于搜索 guard。
- 解析成功的 ResultSet 引用会强制 `target=resolved_result_set_items`、`shouldSearch=false`。
- link/DOI/PDF/source 请求命中 ResultSet 时可直接 deterministic answer，不需要 planner/API。

并保留 v6 migration self-heal，确保 `research_artifacts` 表存在。
