# 引用链工具 + 多步推理引导

Status: ACTIVE
Audience: implementer
Action: read-and-implement
Supersedes: none
Next: 实施后写 completion notes 到 `review/`

## 背景

当前 Agent 有 3 个工具（academic_search、read_papers、search_local_library），能搜论文和读论文，但做不了以下事情：

1. **引用链导航**：不能查"谁引用了这篇"（前向）和"这篇引用了谁"（后向），无法构建一个研究问题的来龙去脉。
2. **多步推理**：system prompt 是单步指令式的（"要搜索→调 academic_search"），模型几乎不会主动做多步操作（搜 → 验证 → 再搜 → 读 → 对比 → 回答）。
3. **结果验证**：模型不会自检搜索结果是否真的匹配用户需求，拿到什么就直接呈现。

本 brief 解决这三个问题：新增 2 个引用链工具 + 重写 system prompt 引导多步推理。

## 设计原则

- 工具做数据获取（调 API、读文件），模型做判断和推理
- extract_claims、compare_papers、write_review、build_timeline 这些不是工具——模型读到论文内容后自己就能做，靠 system prompt 引导
- loop.ts 不改，10 步上限足够覆盖最复杂的多步任务

## 任务

### Phase 1 — Rust 后端：新增引用链 API（`src-tauri/src/commands/search.rs`）

新增两个 Tauri 命令：

```rust
#[tauri::command]
pub async fn search_paper_citations(paper_id: String, limit: Option<i32>) -> Result<SearchResponse, String>

#[tauri::command]
pub async fn search_paper_references(paper_id: String, limit: Option<i32>) -> Result<SearchResponse, String>
```

实现方式：调 Semantic Scholar API。

**Citations（谁引用了这篇）**：
```
GET https://api.semanticscholar.org/graph/v1/paper/{paper_id}/citations
  ?fields=paperId,title,abstract,year,publicationDate,citationCount,authors,url,openAccessPdf,venue,journal,externalIds
  &limit={limit}
```

**References（这篇引用了谁）**：
```
GET https://api.semanticscholar.org/graph/v1/paper/{paper_id}/references
  ?fields=paperId,title,abstract,year,publicationDate,citationCount,authors,url,openAccessPdf,venue,journal,externalIds
  &limit={limit}
```

`paper_id` 支持多种格式（Semantic Scholar API 原生支持）：
- Semantic Scholar ID: `649def34f8be52c8b66281af98ae884c09aef38b`
- DOI: `DOI:10.1234/example`
- arXiv: `arXiv:2301.00001`
- ACL: `ACL:P19-1285`

默认 limit: 20，最大 50。

返回的每条结果复用现有 `SearchResult` 结构，通过 `annotate_result` 补充 `quality_score` 等元数据（使用空 tokens 列表，因为引用链不是关键词搜索）。

返回格式复用 `SearchResponse`，`mode` 字段设为 `"citations"` 或 `"references"`。

**注册命令**：在 `src-tauri/src/main.rs` 的 `invoke_handler` 中注册这两个新命令。

**Semantic Scholar rate limit**：Semantic Scholar 无 key 请求限制 100/5min。已有 `SEMANTIC_SCHOLAR_API_KEY` 环境变量支持（`search.rs:922`），新命令复用同样的 header 逻辑。

```typescript
export async function searchCitations(
  paperId: string,
  limit?: number,
  signal?: AbortSignal,
): Promise<SearchResponse> {
  if (hasTauriInvoke()) {
    return invokeTauri<SearchResponse>('search_paper_citations', {

      limit: limit ?? 20,

  return res.json()
```

#### 3.2 新增工具实现（`src/agent/tools/citation-search.ts`）

新建文件，不超过 60 行：

```typescript
import { searchCitations, searchReferences, type SearchResult } from '../../services/search.ts'

export interface CitationSearchResult {
  paper_id: string
  direction: 'citations' | 'references'
  total: number
  results: Array<{
    index: number
    title: string
    authors: string[]
    year: number | null
    published_date: string | null
    doi: string | null
    source: string
    source_url: string
    abstract_snippet: string | null
    citation_count: number
    journal: string | null
  }>
}

function formatResult(result: SearchResult, index: number) {
  return {
    index,
    title: result.title,
    authors: result.authors.map((a) => a.name),
    year: result.year,
    published_date: result.published_date,
    doi: result.doi,
    source: result.source,
    source_url: result.source_url,
    abstract_snippet: result.abstract_text ? result.abstract_text.slice(0, 1200) : null,
    citation_count: result.citation_count,
    journal: result.journal,
  }
}

export async function executeCitationSearch(
  rawArgs: Record<string, unknown>,
  signal?: AbortSignal,
): Promise<CitationSearchResult> {
  const paperId = typeof rawArgs.paper_id === 'string' ? rawArgs.paper_id.trim() : ''
  if (!paperId) return { paper_id: '', direction: 'citations', total: 0, results: [] }
  const response = await searchCitations(paperId, 20, signal)
  return {
    paper_id: paperId,
    direction: 'citations',
    total: response.results.length,
    results: response.results.map((r, i) => formatResult(r, i + 1)),
  }
}

export async function executeReferenceSearch(
  rawArgs: Record<string, unknown>,
  signal?: AbortSignal,
): Promise<CitationSearchResult> {
  const paperId = typeof rawArgs.paper_id === 'string' ? rawArgs.paper_id.trim() : ''
  if (!paperId) return { paper_id: '', direction: 'references', total: 0, results: [] }
  const response = await searchReferences(paperId, 20, signal)
  return {
    paper_id: paperId,
    direction: 'references',
    total: response.results.length,
    results: response.results.map((r, i) => formatResult(r, i + 1)),
  }
}
```

```
## 可用工具

- academic_search(query) — 搜索外部学术数据库，返回按日期排序的论文列表
- read_papers(papers) — 临时读取论文全文（开放 PDF）或摘要，每次最多 5 篇
- search_local_library(query) — 搜索用户本地已导入的文献库
- search_citations(paper_id) — 查询谁引用了指定论文（前向：影响力和后续工作）
- search_references(paper_id) — 查询指定论文引用了哪些文献（后向：理论基础和前置工作）

## 工作方式

你可以在一轮对话中多次调用工具。每次工具返回结果后，你都可以决定下一步：继续调工具还是回答用户。

### 搜索
- query 用英文，把日期信息写进 query（如 "transformer papers May 2026"）
- 拿到结果后先检查：结果是否匹配用户要的时间、主题、领域？如果不匹配，换一个更精准的 query 重新搜索
- 搜索结果按日期排序返回，你来判断哪些论文最相关、最重要

### 深度分析
- 用户要分析/总结/对比论文时，先调 read_papers 读取全文，再基于内容回答
- 如果 evidence_level 是 abstract_only 或 metadata_only，明确告知用户你没读到全文，不要假装读过
- 分析论文时关注：核心主张、方法机制、实验证据、局限性、与前人工作的关系

### 引用链和研究脉络
- 用户问"这篇论文的影响""有哪些后续工作" → search_citations
- 用户问"这篇论文基于什么""前置工作有哪些" → search_references
- 构建研究脉络时的典型流程：
  1. search_references 看前置工作 → 理解问题从哪里来
  2. read_papers 读关键前驱论文 → 看到前人面对的困境
  3. read_papers 读目标论文 → 看到作者的突破
  4. search_citations 看后续工作 → 看到这个突破带来了什么
- paper_id 可以用 DOI（"DOI:10.1234/example"）或 arXiv ID（"arXiv:2301.00001"）

### 引用上下文
- 用户引用之前的论文（"这几篇""上面那些""刚才搜到的"等）→ 从对话历史中找到对应论文，不要要求用户重新指定
- 从搜索结果中可以拿到 DOI 和 source_url，用它们作为 paper_id 调用引用链工具

### 普通对话
- 普通闲聊、问日期、问你是谁 → 直接回答，不需要调用工具

## 输出要求

- 所有回答基于工具返回的真实数据，不要编造论文信息
- 使用简体中文和 Markdown
- 列出论文时包含：标题、作者、年份、来源、DOI、链接
- read_papers 是临时读取开放 PDF，不会导入用户文献库

## 约束

- read_papers 每次最多 5 篇
- 不要在一轮中调用超过 5 次工具
- 不要建议 Sci-Hub
```

关键变更：
- 从"单步指令"改为"多步推理引导"
- 明确写出引用链导航的典型流程（4 步 timeline 构建）
- 加入搜索结果自检："不匹配就重搜"
- 加入证据等级守卫："abstract_only 要告知用户"
- 工具调用上限从 3 → 5（引用链探索需要更多步骤）

```typescript
  const adapter = new ScriptedAdapter([
```
