## 0. Review Decision

**Request Changes. 不建议合并。**

这次实现不是空架子：`reference-resolver.ts`、`context-pack.ts`、`tool-manifest.ts`、`compression.ts` 确实接入了 `runResearchHarness()`，`npm run build` 和 `cargo check` 也通过。

但它还没有达到 `2026-05-03.06.active.brief.agent-context-pack-tool-runtime.md` 的架构目标。

目前最大问题是：实现把新架构叠在旧 harness 上，但没有真正收敛旧链路；更严重的是，指代消解现在会主动制造新的上下文误绑定。这个问题如果不修，会让 Lumen 看起来“更像 Agent”，但实际更容易答错对象。

请不要把这次实现标记为完成，也不要把 `.06` 移到 done。先修下面 4 个问题。

## 1. P0: 裸 pronoun 会误绑定到旧搜索结果集

位置：

- `src/agent/tools.ts:189-246`

现状：

`referencesExistingResultSet()` 把下面这些词直接当作已有搜索结果集引用：

```text
这些 / 它们 / 他们
```

这太激进了。

只要当前项目里有 active result set，用户搜索完论文后，中间聊了别的内容，再问：

```text
这些分类有什么区别？
它们之间是什么关系？
```

系统就可能把“这些/它们”解析成 R1 前几篇论文。随后 runtime 还会强制：

```ts
target = 'resolved_result_set_items'
shouldSearch = false
```

这会直接复现用户最不能接受的问题：**模型看起来有上下文，但它绑定错了上下文。**

### 必须修改

裸 pronoun 不能直接绑定 result set。

只有以下强锚点才允许绑定已有搜索结果集：

- 明确编号：`R1`、`R1-1`、`R1 前 5 篇`
- 明确序号：`第 1 篇`、`前 5 篇`
- 明确论文结果集语义：`刚才那 10 篇论文`、`你刚才筛出来的论文`
- 明确链接/DOI/PDF 请求且最近 assistant 输出确实是论文结果列表

不允许：

```text
这些
它们
他们
那几个
这几个
```

在没有强锚点时直接绑定 result set。

### 建议实现

拆成两个判断：

```ts
function hasStrongResultSetAnchor(text: string): boolean
function hasWeakPronounOnly(text: string): boolean
```

`resolveResultSetReference()` 只有在 `hasStrongResultSetAnchor(text)` 为 true 时才返回 result set。

如果只是 weak pronoun，交给 `resolveUserQuestion()` 根据最近消息主题判断；如果无法判断，放行给 planner 或 clarify，不要强绑 R1。

### 验收

必须通过：

1. 搜索上周 AI 论文，得到 R1。
2. 问“机器学习有哪些分类？”，正常回答分类。
3. 追问“这些分类有什么区别？”
4. 不能引用 R1 论文，不能进入 `resolved_result_set_items`。

同时必须保留：

```text
R1 前 5 篇做报告
刚才那 10 篇论文的前 5 篇做报告
把 R1-1 到 R1-5 的链接拿出来
```

## 2. P1: “它”会拦截普通对话

位置：

- `src/agent/reference-resolver.ts:45-72`

现状：

`resolveUserQuestion()` 只要看到：

```text
这篇 / 这个论文 / 那篇 / 它 / 该论文 / 刚才那篇
```

如果没有 `currentPaper`，就直接返回 ambiguity：

```text
用户使用“这篇/它”等指代，但当前没有唯一论文对象。
```

这会误伤普通对话。

例如用户在讨论架构时问：

```text
它和 workflow 有什么区别？
它为什么不能这样设计？
```

系统会错误回复“没有唯一论文对象”。这不是 Agent，这是过度拦截。

### 必须修改

`它` 不能天然等于论文。

只有满足以下条件之一，才进入 paper resolver：

- 当前有 `currentPaper`
- 用户文本明确包含论文语义：`论文 / paper / DOI / arXiv / PDF / 摘要 / 方法 / 实验 / 结论`
- 用户文本包含结果集锚点：`R1`、`第 N 篇`、`前 N 篇`
- 最近一轮 assistant 明确刚输出单篇论文详情，且 active object 是 paper

否则应返回：

```ts
standaloneQuestion = input.userText
confidence = low/medium
```

并放行给 planner，不要提前 clarify。

### 验收

必须通过：

```text
它和 workflow 有什么区别？
```

在没有 currentPaper 时，不能回复“没有唯一论文对象”。

同时必须通过：

```text
这篇论文的结论是什么？
```

在有 currentPaper 时，仍走 paper preview。

## 3. P1: ContextPack 没有真正承载 toolResults

位置：

- `src/agent/context-pack.ts:41-99`

现状：

`buildContextPack()` 保存了：

```ts
toolResults: options.toolResults ?? []
```

但是 `formatContextPackForModel()` 完全没有渲染 `toolResults`。

这意味着：

- `synthesizeAnswer()` 传入的 `SearchBatch[]` 不在 ContextPack 中出现。
- `synthesizePaperDetail()` 传入的 `detailContext` 不在 ContextPack 中出现。
- 主模型真正依赖的仍然是后面拼接的旧 prompt：`buildSynthesisUserPrompt()`、`buildPaperDetailUserPrompt()`。

所以现在的 ContextPack 不是主模型的权威上下文，只是旧 prompt 前面的一段装饰说明。

这不符合 `.06` 的目标。

### 必须修改

ContextPack 必须渲染 typed tool results。

建议先支持这些类型：

```ts
type ContextToolResult =
  | { type: 'search_batches'; batches: SearchBatch[] }
  | { type: 'paper_detail'; text: string }
  | { type: 'paper_preview'; text: string; evidenceLevel: string }
  | { type: 'local_papers'; text: string }
```

然后 `formatContextPackForModel()` 必须输出：

```text
## 工具执行结果
### academic_search
...

### paper_detail
...
```

不要把 `unknown[]` 丢进去然后不渲染。

### 可接受的过渡方案

短期可以保留旧 prompt 拼接，避免大面积行为回归。

但必须做到：

- ContextPack 本身已经包含足够回答的信息。
- 旧 prompt 只是兼容层，不是唯一证据来源。
- completion notes 必须明确哪些旧 prompt 仍保留，为什么保留，下一步如何删除。

### 验收

在 trace 或调试输出中检查 synthesis prompt。

必须能看到 ContextPack 内包含：

- 搜索结果标题、作者、URL/DOI/PDF URL
- paper detail 文本
- evidence level
- warnings

如果删掉后面的旧 prompt，ContextPack 仍应足以让模型回答基本问题。

## 4. P2: Planner 仍然固定截断最近对话

位置：

- `src/agent/guides.ts:325-343`

现状：

虽然新增了 `maybeCompressChatHistory()`，但 planner 仍然固定：

```ts
messages.slice(-10)
message.content.slice(0, 600)
```

这不是按 1M context budget 的 compression hook，而是固定有损截断。

结构化 result set 保住了，但普通话题、非论文指代、用户偏好和刚才讨论的概念仍会丢。

### 必须修改

短期至少做到：

- 不要叫 `compression hook`，实际却仍固定截断。
- `compactRecentMessages()` 应接收 compression result 或 budget。
- 未接近 budget 时，保留更多最近上下文。
- 如果仍要截断，必须说明这是 planner prompt budget，不是全局 context compression。

建议：

```ts
buildPlannerRecentMessages(messages, budgetState)
```

其中 `budgetState.compressionApplied=false` 时，不做强压缩，只做安全上限。

### 验收

用户在搜索论文后，连续聊 8-12 轮架构问题，再问：

```text
刚才我们说的 workflow 和 agent 的区别是什么？
```

不应该被结果集 resolver 抢走，也不应该完全失去最近讨论主题。

## 5. 关于“新增多，删除少”

新增多不是原罪。

但这次实现的问题是：**新增层没有替代旧责任，导致职责重叠。**

现在有三套东西同时在做上下文：

1. `history`
2. 旧 synthesis prompt
3. 新 ContextPack

这会让模型输入变长、重复、甚至互相矛盾。

下一步不要求一次性大删，但要求明确方向：

- `ResolvedUserQuestion` 负责本轮问题语义完整。
- `ContextPack` 负责给主模型的权威证据和对象。
- 旧 `buildSynthesisUserPrompt()` 只能作为兼容层，不能继续承载唯一事实。
- `ToolManifest` 不只是展示给模型看，runtime guard 必须根据它执行边界。
