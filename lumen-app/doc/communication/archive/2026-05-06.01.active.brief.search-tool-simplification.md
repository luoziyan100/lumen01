# 搜索工具简化：让模型做判断，工具只做执行

Status: ACTIVE
Audience: implementer
Action: read-and-implement
Supersedes: none
Next: 实施后写 completion notes 到 `review/`

## 背景

用户要求"搜索今天的论文"，但返回的全是老论文。根本原因：

1. 工具参数过多（6 个），模型选了 `sort: "relevance"`，而后端 relevance 排序用硬编码 `quality_score`（期刊等级 + 引用数），高引用老论文把今天的新论文挤掉。
2. 模型生成了 `time_range: "today"` 而非合法的 `YYYY-MM-DD`，后端忽略了无效日期。
3. 返回给模型的结果没有 `published_date`，只有 `year`，模型无法判断哪些是今天发的。

参考 Claude Code 的 WebSearch 实现（源码已分析），它的工具只有一个参数：`query`。没有 `time_range`、`sort`、`mode`、`limit`。日期通过 system prompt 的 `currentDate` 传递，模型自己把日期信息写进 query。结果不排序不截断，由模型判断重要性。

## 设计原则

**工具只是手脚，脑子在模型里。**

- 搜索工具负责：接收 query → 调 API → 返回原始结果
- 模型负责：构造好的 query、判断哪些结果重要、向用户呈现

### Phase 2 — 修改搜索执行层（`src/agent/tools/academic-search.ts`）

#### 2.1 入口改为单 query

```typescript
export async function executeAcademicSearch(
  rawArgs: Record<string, unknown>,
  signal?: AbortSignal,
): Promise<AcademicSearchResult> {
  const query = typeof rawArgs.query === 'string' ? rawArgs.query.trim() : ''
  if (!query) return { total: 0, results: [] }
  const batches = [await searchPapers(query, 20, { sortMode: 'newest' }, signal)]
  const merged = mergeSearchBatches(batches, 20)
  return {
    total: merged.length,
    results: merged.map((r, i) => formatResult(r, i + 1)),
  }
}
```

关键变更：
- 单 query string，不再是数组
- 固定 `sortMode: 'newest'`，让后端按日期排
- `limit` 固定 20，给模型看足够多的结果
- 不传 `time_range`——模型自己把日期写进 query，后端 API 会按关键词匹配

#### 2.2 `mergeSearchBatches` 排序改为按日期

```typescript
export function mergeSearchBatches(batches: SearchBatch[], limit: number): SearchResult[] {
  // ... 合并去重逻辑不变 ...
  return Array.from(byKey.values())
    .sort((a, b) => {
      // 优先按日期降序（最新的在前）
      const dateA = a.published_date ?? ''
      const dateB = b.published_date ?? ''
      if (dateA !== dateB) return dateB.localeCompare(dateA)
      // 日期相同按 quality_score（保留作为次要参考）
      return b.quality_score - a.quality_score
    })
    .slice(0, limit)
}
```

#### 2.3 `formatResult` 增加 `published_date`

```typescript
function formatResult(result: SearchResult, index: number): AcademicSearchResult['results'][number] {
  return {
    index,
    title: result.title,
    authors: result.authors.map((a) => a.name),
    year: result.year,
    published_date: result.published_date,  // 新增
    doi: result.doi,
    source: result.source,
    source_url: result.source_url,
    abstract_snippet: result.abstract_text ? result.abstract_text.slice(0, 1200) : null,  // 800 → 1200
    open_access_url: result.open_access_pdf_url ?? result.open_access_url ?? result.open_access_landing_url,
    citation_count: result.citation_count,
    journal: result.journal,  // 新增，让模型自己判断期刊重要性
  }
}
```

新增字段：`published_date`、`journal`。摘要截断从 800 → 1200 字符。

### Phase 3 — 更新 system prompt（`src/agent/system-prompt.ts`）

在工作原则中更新搜索指导：

```
- 用户要搜索/推荐/查找论文 → 调用 academic_search，把关键词和日期约束写进 query
  - query 用英文
  - 把日期信息直接写进 query（如 "transformer architecture papers May 2026"），不要单独传日期参数
  - 搜索结果按日期排序返回，你来判断哪些论文最相关、最重要
```

删除旧的 `academic_search 的 queries 用英文` 约束（改为新的单数形式）。

### Phase 4 — Rust 后端 `quality_score` 权重调整（`src-tauri/src/commands/search.rs`）

这一步是**可选优化**，不做也不会阻塞功能。当前后端在 `newest` 排序模式下已经以日期为主排序（`search.rs:1536-1545`），所以 Phase 2 传 `sortMode: 'newest'` 后，新论文会排在前面。

如果要做，调整 `annotate_result` 中的权重：

- `tier_score`：从 `55/35/20` 降到 `8/5/3`（期刊信息保留但不再主导排序）
- `citation_score`：从 `ln(count) * 8` 降到 `ln(count) * 2`（引用数作为参考信号，不是排序依据）

**注意**：`TOP_JOURNALS` 列表偏向神经科学，缺少 CS/AI 顶会（NeurIPS、ICML、ICLR、ACL、CVPR 等）。如果调整权重，这个偏差可以暂时忽略；如果保留高权重，必须补充 CS/AI 会议。但更好的做法是大幅降低 `tier_score` 权重，让模型自己判断期刊重要性。

## DO NOT

1. **不要保留 `queries` 数组参数**。单 query string，跟 Claude Code 一样。如果模型需要多角度搜索，它会在多个 loop step 里分别调用。
2. **不要保留 `time_range` 参数**。日期写进 query string。
3. **不要保留 `sort` 参数**。固定 newest。
4. **不要保留 `mode` 和 `arxiv_categories` 参数**。后端统一走 keyword_search + 四源并发。
5. **不要在 `mergeSearchBatches` 或 `formatResult` 中按 `quality_score` 截断**。排序可以用 `quality_score` 作为次要信号，但主排序是日期。
6. **不要改 `read_papers` 和 `search_local_library` 工具**。本次只改 `academic_search`。
7. **不要改适配器层（`adapters/`）**。
8. **不要删除 Rust 后端的 `quality_score` 计算**。它可以作为元数据传给模型参考，但不能用来在模型看到之前截断结果。
