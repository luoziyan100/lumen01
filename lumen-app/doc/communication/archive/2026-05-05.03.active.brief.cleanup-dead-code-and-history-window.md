### Phase 2 — Agent 对话历史窗口管理（1 小时）

#### 问题

当前 `ResearchPage` 每次 `handleSend` 都把完整 `agentHistory`（所有 user + assistant + tool_result 消息）序列化为 JSON 写入 `research_notes`。10 轮对话后，每条 note 可能数十 KB，且是全量重复快照。

更重要的是，发给 LLM 的 `conversationHistory` 也是全量。长对话会超出 context window。

#### 方案

在 `src/agent/` 下新建 `history-window.ts`（不超过 80 行），提供：

```typescript
export interface HistoryWindowOptions {
  maxMessages?: number      // 默认 40
  maxToolResults?: number   // 默认 20
  preserveLatestN?: number  // 最近 N 条完整保留，默认 10
}

export function trimHistory(
  history: AgentMessage[],
  options?: HistoryWindowOptions,
): AgentMessage[]
```

策略：

1. 最近 `preserveLatestN` 条消息完整保留（包括 tool_result）。
2. 更早的消息中，如果 `tool_result` 数量超过 `maxToolResults`，只保留每条 tool_result 的前 500 字符（截断后加 `...[truncated]`）。
3. 如果总消息数超过 `maxMessages`，从头部开始删除最老的 user/assistant 对（保留 tool_result 不删，因为它们是 agent 的"记忆"）。
4. 永远不删除 system 消息。

#### 集成

在 `loop.ts` 中，构建 messages 时对 `input.conversationHistory` 调用 `trimHistory`：

```typescript
const messages: AgentMessage[] = [
  { role: 'system', content: buildSystemPrompt(input.context) },
  ...trimHistory(input.conversationHistory),
  { role: 'user', content: input.userText, images: input.images },
]
```

#### ResearchPage 存储优化

在 `ResearchPage.tsx` 中，存储 agentHistory 时不再全量快照。改为：

- 只在 **session 结束**（用户切换项目或关闭）时写入一次完整快照，而不是每轮写一次。
- 每轮对话只追加 `addResearchNote(projectId, 'user', text)` 和 `addResearchNote(projectId, 'assistant', reply)`，不写 `agent_history` note。
- 加载项目时，从 user/assistant notes 重建基础历史（这已经是 `agentHistoryFromNotes` 的 fallback 逻辑）。但这会丢失 tool_result。

更好的方案：**每轮追加增量**。把 `agentResult.newMessages`（通常 2-4 条：assistant + tool_result + assistant）序列化为一条 `agent_history_delta` note。加载时按顺序拼接所有 delta。

```typescript
// 存储（每轮）
await addResearchNote(projectId, 'agent_history_delta', JSON.stringify([
  { role: 'user', content: text, images },
  ...agentResult.newMessages,
]))

// 加载
function agentHistoryFromNotes(notes: ResearchNote[]): AgentMessage[] {
  const deltas = notes
    .filter(n => n.role === 'agent_history_delta')
    .flatMap(n => {
      try { return JSON.parse(n.content) as AgentMessage[] }
      catch { return [] }
    })
  return deltas
}
```

同时兼容旧的 `agent_history` 全量快照格式（向后兼容加载老数据）。
