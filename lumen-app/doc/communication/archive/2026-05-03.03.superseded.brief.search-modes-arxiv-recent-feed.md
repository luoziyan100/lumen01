## 1. 当前判断

用户实测：

```text
Lumen 搜索“上周 AI 领域论文”只返回几篇。
OpenClaw 用 arXiv 分类 + 日期区间枚举，得到约 1400+ 篇。
```

这不是模型回答风格问题，而是搜索范式问题。

Lumen 当前更像：

```text
keyword_search:
  query="AI"
  arXiv search_query=all:AI
  per_source=4..15
  merge top results
```

用户这个需求实际是：

```text
recent_ai_feed:
  arXiv categories = cs.AI, cs.LG, cs.CL, cs.CV, cs.RO, stat.ML
  submittedDate=[from TO until]
  sortBy=submittedDate
  paginate / count / sample / summarize
```

关键词 `AI` 不等于 AI 领域。很多 AI 论文标题/摘要不会出现 `AI`，而会写：

- reinforcement learning
- language model
- multimodal
- reasoning
- diffusion
- agent
- alignment
- world model
- video generation

所以 `all:AI` 会大量漏召回。

## 2. P0 Finding: arXiv 搜索只走 all:{query}

位置：

- `src-tauri/src/commands/search.rs:1093-1110`
- `vite.config.ts:546-554`

现状：

```text
search_query=all:{query}
```

问题：

用户问“4 月 27 日以来 AI 领域论文”，planner 可能生成 `AI` 或 `artificial intelligence`，于是 arXiv 查的是 `all:AI`，不是 AI 分类全集。

建议：

为 arXiv 新增分类 feed 查询：

```text
(cat:cs.AI OR cat:cs.LG OR cat:cs.CL OR cat:cs.CV OR cat:cs.RO OR cat:stat.ML)
AND submittedDate:[YYYYMMDD0000 TO YYYYMMDD2359]
```

## 3. P0 Finding: 每源 limit 太小，不适合 feed 枚举

位置：

- `src-tauri/src/commands/search.rs:1301-1314`
- `vite.config.ts:559-570`

现状：

```rust
let requested_limit = limit.unwrap_or(12).clamp(4, 40);
let per_source = ((requested_limit + 3) / 4).max(4).min(15);
```

问题：

这个逻辑适合“给我推荐几篇论文”，但不适合“从某日期开始 AI 领域一共有多少论文 / 有哪些新论文”。

对 feed 模式应支持：

- 单源 arXiv 优先。
- `max_results` 可以到 100 或更高。
- 分页拉取。
- 返回 `totalCount` / `fetchedCount` / `sampledResults`。

不要把 feed 枚举硬塞进多源 top-K 搜索。

## 4. 推荐搜索模式

新增显式搜索模式，而不是让模型每次自由拼 query。

建议：

```ts
export type SearchMode =
  | 'keyword_search'
  | 'paper_lookup'
  | 'recent_ai_feed'
  | 'arxiv_category_feed'
```

扩展 `SearchPlan`：

```ts
interface SearchPlan {
  searchMode?: SearchMode
  sourceHint?: 'all' | 'arxiv' | 'openalex' | 'semantic_scholar' | 'crossref'
  categoryPreset?: 'ai' | 'llm' | 'vision' | 'robotics' | 'custom'
  arxivCategories?: string[]
  feedLimit?: number
  includeTotalCount?: boolean
}
```

Planner 只负责判断模式：

- “找几篇相关论文 / 推荐论文” -> `keyword_search`
- “这篇论文 / DOI / 精确标题” -> `paper_lookup`
- “上周 AI 论文 / 最近 AI 领域论文 / 4月27日以来 AI 论文” -> `recent_ai_feed`
- “这周 arXiv cs.CL 有什么” -> `arxiv_category_feed`

## 5. arXiv Category Presets

先做可配置常量，不要每次让模型猜。

```ts
const ARXIV_CATEGORY_PRESETS = {
  ai: ['cs.AI', 'cs.LG', 'cs.CL', 'cs.CV', 'cs.RO', 'stat.ML'],
  llm: ['cs.CL', 'cs.AI', 'cs.LG'],
  vision: ['cs.CV', 'eess.IV', 'cs.LG'],
  robotics: ['cs.RO', 'cs.AI', 'cs.LG'],
}
```

说明：

- 这是一种“有意识的硬编码”，不是坏事。
- arXiv 本身就是按分类组织的，领域 feed 应该用分类而不是关键词。
- 后续可以把 preset 移到配置文件。

## 6. arXiv Feed 查询设计

新增函数：

```rust
async fn search_arxiv_feed(
    client: &reqwest::Client,
    categories: &[String],
    from_date: &str,
    until_date: &str,
    limit: i32,
    include_total_count: bool,
) -> ArxivFeedResult
```

查询模板：

```text
search_query=(cat:cs.AI OR cat:cs.LG OR ...)
  AND submittedDate:[202604270000 TO 202605032359]
sortBy=submittedDate
sortOrder=descending
start=0
max_results=100
```

分页：

- arXiv API 每页建议 100。
- `feedLimit` 默认 50，最大可先限制 200。
- 如果用户问“一共有多少”，需要解析 feed 的 `opensearch:totalResults`。
- 不要为了返回 1400 条全文列表一次性塞给模型。可以返回统计 + top/sample。

返回结构建议：

```ts
interface FeedSearchResponse {
  total: number
  fetched: number
  results: SearchResult[]
  mode: 'recent_ai_feed' | 'arxiv_category_feed'
  categories: string[]
  fromDate: string
  untilDate: string
}
```

如果为了兼容现有 `SearchResponse`，可以先在 `SearchResponse` 上加可选字段：

```ts
interface SearchResponse {
  total: number
  results: SearchResult[]
  mode?: SearchMode
  totalAvailable?: number
  categories?: string[]
}
```

## 7. Runtime 接入

`runAcademicSearches()` 需要识别 `plan.searchMode`：

```text
keyword_search:
  继续走 OpenAlex + arXiv keyword + Semantic Scholar + Crossref

recent_ai_feed:
  只走 arXiv feed preset(ai)
  可选再用 OpenAlex/Semantic Scholar 做 enrich，但不要影响总数

arxiv_category_feed:
  只走用户/plan 指定 arXiv categories

paper_lookup:
  优先 DOI/title 精确查询，避免 feed
```

不要把 `recent_ai_feed` 再拆成 4 个来源平均 limit。

## 8. Planner Prompt 改造

`PLANNER_SYSTEM_PROMPT` 增加规则：

```text
- 如果用户问“最近/本周/某日期以来 AI 领域论文有哪些、一共有多少、arXiv 上有什么新论文”，不要生成 query="AI" 做 keyword_search；应设置 searchMode=recent_ai_feed，sourceHint=arxiv，categoryPreset=ai，timeRange=...
- 如果用户指定 arXiv 分类，例如 cs.CL / cs.LG / cs.CV，设置 searchMode=arxiv_category_feed，并填写 arxivCategories。
- 如果用户只是要推荐少量相关论文，仍用 keyword_search。
```

## 9. Answer Behavior

Feed 查询返回结果很多时，回答不要把全部论文列出来。

建议结构：

```text
我按 arXiv 分类 feed 搜索：
cs.AI + cs.LG + cs.CL + cs.CV + cs.RO + stat.ML
日期：2026-04-27 至 2026-05-03
arXiv totalResults：1428
本次拉取：前 100 篇

下面按主题聚类/高层概览：
1. LLM / Agent
2. Multimodal / Vision
3. RL / Robotics
4. Alignment / Safety

如果你要，我可以继续筛 top papers 或进入 deep research。
```

不要把 `totalAvailable` 和 `fetched` 混淆。

## 10. 验收标准

- 用户问“搜索上周 AI 领域论文”，planner 选择 `recent_ai_feed`，而不是 `keyword_search all:AI`。
- arXiv 请求使用 `cat:` 分类 + `submittedDate` 日期区间。
- 对 2026-04-27 至 2026-05-03 的 AI preset，结果数量应显著高于关键词 `all:AI`，并显示 `totalAvailable`。
- 用户问“只推荐几篇 AI 论文”，仍可走 keyword/top-K，不强制 feed。
- 用户问“这周 cs.CL 有什么”，走 `arxiv_category_feed`，categories 包含 `cs.CL`。
- feed 模式不受 per-source 4-15 限制。
- 回答说明搜索模式、分类、日期、总数和本次拉取数。
- Evidence Gate 后续可以对 feed 的 top papers 继续做 PDF preview，但 feed 本身先解决召回。
