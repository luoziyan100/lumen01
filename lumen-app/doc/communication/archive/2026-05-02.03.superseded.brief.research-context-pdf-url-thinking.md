## 1. PR 目标

这次 PR 的最高优先级不是 PDF，而是研究 Agent 的上下文闭环。

用户复现：

```text
用户：他是怎么定义啊哈 moment？
系统：没有可引用的最近搜索结果。请先搜索论文，或提供论文标题/DOI。
用户：这个不是我们这个对话的论文吗？
系统：当前对话上下文中没有导入或搜索过具体论文……
```

页面上看起来有连续聊天历史，但 Agent 的工具层拿不到“最近搜索结果 / 当前讨论论文”。这会让用户觉得上下文丢失。

本 PR 需要修三类问题：

- P0：研究页只持久化聊天文本，没有持久化结构化搜索结果和当前讨论论文，导致“这篇 / 它 / 那篇”经常失效。
- P1：Paper Preview 已经有临时下载和缓存链路，但搜索结果里的 `open_access_url` 混入 landing page，导致系统把网页当 PDF 下载。
- P2：研究页等待状态显示“正在规划回答...”，需要改成动态 `Thinking...`。

## 2. P0 Review Finding: 结构化上下文没有持久化

位置：

- `src/pages/ResearchPage.tsx:45`
- `src/pages/ResearchPage.tsx:80-88`
- `src/pages/ResearchPage.tsx:249-266`
- `src/agent/tools.ts:84-126`
- `src/agent/guides.ts:128-145`
- `src-tauri/src/commands/research.rs:220-265`

现状：

- `ResearchPage` 用 `useState<SearchResult[]>([])` 保存 `lastSearchResults`。
- 搜索完成后只通过 `setLastSearchResults(agentResult.searchResults)` 存在前端内存里。
- `addResearchNote(projectId, 'assistant', reply)` 只保存 assistant 文本，不保存 `searchResults`、`plan`、`trace` 或 artifacts。
- `loadProject()` 重新加载项目时会 `setLastSearchResults([])`。
- planner 只看最近 6 条文本消息，每条裁剪到 600 字。
- `resolvePaperReference()` 如果 `lastSearchResults.length === 0`，直接报“没有可引用的最近搜索结果”。

根因：

```text
聊天历史可见 != Agent 结构化上下文可用
```

用户看到的对话在，但工具执行需要的 `lastSearchResults` 已经丢了。只靠 assistant 的自然语言回答反推论文对象不可靠，也不应该让模型猜。

## 3. P0 推荐实现方案

### 3.1 引入 Research Artifact

建议新增一个轻量 artifact 持久化层，不要把结构化状态塞进纯文本 note。

可选方案 A：扩展 `research_notes`

```ts
interface ResearchNote {
  id: string
  project_id: string
  role: string
  content: string
  created_at?: string
  metadata_json?: string
}
```

assistant note 可保存：

```json
{
  "agentPlan": {},
  "searchResults": [],
  "currentPaper": {},
  "traceId": "..."
}
```

可选方案 B：新增 `research_artifacts` 表，更干净：

```sql
CREATE TABLE research_artifacts (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES research_projects(id) ON DELETE CASCADE,
  note_id TEXT REFERENCES research_notes(id) ON DELETE SET NULL,
  type TEXT NOT NULL,
  data_json TEXT NOT NULL,
  created_at TEXT DEFAULT (datetime('now'))
);
```

推荐方案 B。原因：后续会有 `search_results`、`paper_preview`、`deep_research_report`、`import_candidate` 等多种 artifact，单独表更好演进。

### 3.2 至少持久化这些 artifact

搜索完成后保存：

```ts
{
  type: 'search_results',
  data: {
    results: SearchResult[],
    query: string,
    createdAt: string
  }
}
```

paper detail / preview 成功解析后保存：

```ts
{
  type: 'current_paper',
  data: {
    paper: SearchResult,
    evidenceLevel: 'metadata_only' | 'abstract_only' | 'pdf_text_preview',
    source: 'paper_detail' | 'paper_preview',
    createdAt: string
  }
}
```

注意：

- `current_paper` 是“当前对话正在讨论哪篇论文”的显式状态。
- 它不等于导入文献库，不应保存 PDF 到永久文献库。

### 3.3 页面加载项目时恢复上下文

`loadProject(projectId)` 不能再直接 `setLastSearchResults([])`。

应该：

- 加载 notes。
- 加载该 project 最近的 `search_results` artifact。
- 恢复 `lastSearchResults`。
- 加载最近的 `current_paper` artifact。
- 恢复 `currentPaper` 或放入 `AgentInputContext`。

### 3.4 AgentInputContext 增加 currentPaper

建议：

```ts
interface AgentInputContext {
  currentDate: string
  timezone: string
  hasLocalPapers: boolean
  localPaperCount: number
  activeProjectName?: string
  selectedPaperTitle?: string
  lastSearchResults?: SearchResult[]
  currentPaper?: SearchResult
}
```

planner prompt 中明确说明：

```text
如果用户说“这篇 / 它 / 这个论文 / 这篇文章”，优先指向 currentPaper。
如果没有 currentPaper，但 lastSearchResults 只有一篇，可以指向该结果。
如果 lastSearchResults 多篇且没有 currentPaper，才要求用户说第几篇。
```

### 3.5 resolvePaperReference 支持 currentPaper

`resolvePaperReference()` 现在只接受 `lastSearchResults`，建议改成：

```ts
resolvePaperReference(plan, userText, {
  currentPaper,
  lastSearchResults,
})
```

规则：

- 用户说“这篇 / 它 / 该论文 / 这个论文”时，如果有 `currentPaper`，直接返回 currentPaper。
- 用户说“第 N 篇”时，用 `lastSearchResults[N - 1]`，并把它设置为新的 currentPaper。
- 用户给 DOI/title/sourceUrl 时，先在 currentPaper 和 lastSearchResults 里查。
- 都失败才 clarify。

### 3.6 recentMessages 不要只传旧 messages

`ResearchPage.tsx:252` 现在传的是发送前的 `messages`，不包含当前 user message。虽然 `buildPlannerUserPrompt` 另有 `userText`，但 recent messages 用于指代解析时最好包含当前回合之前的最近上下文，并且不应只靠纯文本。

建议保留当前做法也可以，但必须让 `AgentInputContext` 带上 `currentPaper` 和恢复后的 `lastSearchResults`。否则文本窗口再长也不稳定。

## 4. P1: 修复 Paper Preview PDF URL 语义

### 4.1 Review Findings

位置：

- `src-tauri/src/commands/search.rs:690-712`
- `vite.config.ts:383-386`
- `src/services/search.ts:67`
- `src-tauri/src/commands/files.rs:85-96`
- `vite.config.ts:601-613`

问题：

- OpenAlex 的 `open_access.oa_url` 和 `best_oa_location.landing_page_url` 经常是网页，不是 PDF。
- UI 只要有 `open_access_url` 就显示 `[PDF]`。
- PDF 校验只要 URL 包含 `.pdf` 就可能通过，可能缓存 HTML。

### 4.2 推荐字段拆分

```ts
interface SearchResult {
  open_access_pdf_url: string | null
  open_access_landing_url: string | null
  source_url: string
}
```

如果为了兼容暂时保留 `open_access_url`，它必须只表示 direct PDF URL，不允许放 landing page。

### 4.3 OpenAlex 映射规则

```text
open_access_pdf_url =
  primary_location.pdf_url
  ?? best_oa_location.pdf_url
  ?? null
```

```text
open_access_landing_url =
  open_access.oa_url
  ?? best_oa_location.landing_page_url
  ?? primary_location.landing_page_url
  ?? null
```

```text
source_url =
  primary_location.landing_page_url
  ?? open_access.oa_url
  ?? OpenAlex id
```

Semantic Scholar 的 `openAccessPdf.url` 可以进入 direct PDF。arXiv 的 `title="pdf"` link 可以进入 direct PDF。Crossref 默认不要填 direct PDF。

### 4.4 Paper Preview 只读取 direct PDF

`src/services/paper-preview.ts` 应只在 `paper.open_access_pdf_url` 存在时调用 `fetchPdfBytes`。没有 direct PDF 时自然降级为摘要/元信息，不要拿 landing page 尝试下载。

### 4.5 PDF 校验必须看响应体

Tauri 和 Vite dev proxy 都要在缓存前检查 bytes：

```text
is_pdf = bytes first 1024 bytes contains "%PDF"
if !is_pdf => reject and do not cache
```

`Content-Type` 和 URL 后缀只能辅助诊断，不能作为最终通过条件。

## 5. P2: Thinking 动态状态

位置：

- `src/pages/ResearchPage.tsx:594`

当前：

```tsx
<span className="t-body-sm">正在规划回答...</span>
```

目标：

```text
Thinking
Thinking.
Thinking..
Thinking...
```

实现建议：

- 保留现有 spinner。
- 新增 `ThinkingStatus` 子组件。
- 用 `useEffect` + `setInterval` 更新 dots。
- 组件卸载时清理 interval。

示例：

```tsx
function ThinkingStatus() {
  const [dots, setDots] = useState('')

  useEffect(() => {
    const id = window.setInterval(() => {
      setDots((current) => (current.length >= 3 ? '' : `${current}.`))
    }, 400)
    return () => window.clearInterval(id)
  }, [])

  return <span className="t-body-sm">Thinking{dots}</span>
}
```

## 6. 验收标准

- 在同一研究项目中，搜索论文后刷新页面或切换项目再回来，Agent 仍知道最近搜索结果。
- 用户问“这篇 / 它 / 这个论文”时，如果已经进入某篇 paper preview/detail，应默认指向 `currentPaper`。
- 用户问“第 2 篇讲什么”后，再问“它怎么定义 aha moment”，应继续指向第 2 篇。
- 如果没有 currentPaper 且最近搜索结果多篇，才要求用户选择第几篇。
- 搜索结果里的 `[PDF]` 只出现在 direct PDF URL 存在时。
- OpenAlex landing page 不再进入 Paper Preview 下载链路。
- 非 PDF 响应不会写入 Tauri 或 dev proxy 的 PDF 缓存。
- `ResearchPage` loading 状态显示动态 `Thinking...`，dots 会循环变化。
- 不改变“只有用户明确要求保存/导入时才进入文献库”的边界。
