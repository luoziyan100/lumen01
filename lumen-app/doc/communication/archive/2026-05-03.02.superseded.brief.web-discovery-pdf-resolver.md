## 1. 当前判断

上一阶段已经实现：

- Evidence Gate
- `evidenceRequirement`
- `academic_search -> previewEvidencePapers -> synthesizeEvidenceAnswer`
- `deep_research` 多篇 evidence pipeline

但用户实测仍看到：

```text
证据等级：abstract_only
仅有摘要，未获取到全文 PDF
```

这不是主要模型问题。模型正确遵守了 evidence level，没有假装读过全文。

真正缺口是：

```text
没有 direct PDF URL 时，Lumen 缺少二次 PDF resolver / web discovery。
```

现在链路是：

```text
SearchResult.open_access_pdf_url exists
  -> fetch_open_pdf
else
  -> abstract_only
```

目标链路应该是：

```text
SearchResult
  -> direct PDF
  -> DOI / OpenAlex / Semantic Scholar / Unpaywall / Crossref / arXiv
  -> landing page HTML extraction
  -> optional web search discovery
  -> verify %PDF
  -> temporary PDF cache
  -> fallback abstract_only only after attempts fail
```

## 2. Product Boundary

主动获取全文时，Lumen 只允许公开开放 PDF。

允许：

- OpenAlex OA locations
- Unpaywall OA locations
- Semantic Scholar `openAccessPdf`
- arXiv / bioRxiv / medRxiv / PsyArXiv
- OSF / SSRN
- PubMed Central / institutional repositories
- author homepage / lab homepage public PDF
- publisher open PDF
- 用户自己上传或手动导入的 PDF

不允许：

- Sci-Hub resolver
- LibGen resolver
- 绕 paywall
- 自动拼接盗版下载链接
- 需要登录、机构权限、验证码、cookie 盗用的下载

原则：

```text
Lumen 主动获取 = 只拿公开开放 PDF
用户提供材料 = 用户自己负责访问来源，Lumen 可以读取
```

这不是限制用户研究，而是产品边界。Lumen 要做成长期可维护工具，不能内置盗版论文获取能力。

## 3. P1 Finding: Paper Preview 没有二次 resolver

位置：

- `src/services/paper-preview.ts:220-229`

现状：

```ts
const pdfUrl = directPdfUrl(paper)
if (!pdfUrl) {
  return abstract_only / metadata_only
}
```

问题：

Evidence Gate 已经知道“这个问题需要一手材料”，但 `paper-preview` 只看搜索结果里有没有 direct PDF URL。很多论文搜索 API 不直接给 PDF，但 DOI、OSF、SSRN、PsyArXiv、作者主页可能有开放版本。

## 4. P1 Finding: Search Tool 不是 Web Discovery

位置：

- `src-tauri/src/commands/search.rs`
- `vite.config.ts`

现状：

搜索工具主要依赖：

- OpenAlex
- Semantic Scholar
- Crossref
- arXiv

这些适合找 metadata，不等于能找到所有开放 PDF。

需要新增一个独立层：

```text
PDF Resolver / Evidence Acquisition Layer
```

不要把所有责任塞进 `academic_search`。

## 5. 推荐实现方案

### 5.1 新增 PDF resolver 类型

建议新增：

```ts
interface PdfResolutionAttempt {
  source: 'direct' | 'unpaywall' | 'openalex' | 'semantic_scholar' | 'crossref' | 'arxiv' | 'landing_page' | 'web_search'
  status: 'skipped' | 'candidate_found' | 'verified_pdf' | 'not_found' | 'blocked' | 'failed'
  url?: string
  reason?: string
}

interface PdfResolutionResult {
  pdfUrl: string | null
  landingUrl?: string | null
  source?: string
  license?: string | null
  attempts: PdfResolutionAttempt[]
}
```

核心函数：

```ts
async function resolveOpenPdf(paper: SearchResult, signal?: AbortSignal): Promise<PdfResolutionResult>
```

### 5.2 Resolver 优先级

按这个顺序尝试：

```text
1. Existing direct PDF URL
2. arXiv direct PDF from arXiv id/title
3. Semantic Scholar detail by DOI/title
4. OpenAlex work detail by DOI/OpenAlex id/title; inspect primary_location, best_oa_location, locations[]
5. Unpaywall by DOI; inspect best_oa_location and oa_locations url_for_pdf
6. Crossref links / relation URLs, only if verified as PDF
7. Known repository landing pages: OSF, PsyArXiv, SSRN, PMC, author/lab pages
8. Optional web search: exact title + DOI + PDF / author
9. Fail with attempts log, then abstract_only
```

重要：

- 每个 candidate URL 都必须通过 `fetch_open_pdf` 或同等 `%PDF` 校验。
- landing page 不是 PDF；只能作为提取 PDF link 的来源。
- 不要因为 URL 包含 `.pdf` 就信任；最终以 bytes `%PDF` 为准。

### 5.3 Unpaywall

如果 `paper.doi` 存在，优先查询 Unpaywall。

建议：

```text
GET https://api.unpaywall.org/v2/{doi}?email=<configured-email>
```

读取：

- `best_oa_location.url_for_pdf`
- `best_oa_location.url`
- `oa_locations[].url_for_pdf`
- `oa_locations[].url_for_landing_page`
- `license`
- `host_type`
- `version`

如果没有配置 email，可以先用项目 contact email，但后续应该放到配置中。

### 5.4 OpenAlex detail

当前搜索阶段只用部分 location 字段。

Resolver 阶段应按 DOI/OpenAlex id 再查 work detail，并检查：

- `primary_location.pdf_url`
- `best_oa_location.pdf_url`
- `locations[].pdf_url`
- `open_access.oa_url`
- `locations[].landing_page_url`
- `best_oa_location.license`
- `open_access.oa_status`

`oa_url` 可能是 landing page，所以要 fetch HTML 并提取 PDF link，而不是直接当 PDF。

### 5.5 Semantic Scholar detail

按 DOI/title/paperId 查询 detail，读取：

- `openAccessPdf.url`
- `url`
- `externalIds`

如果 `openAccessPdf.url` 存在，仍需 `%PDF` 校验。

### 5.6 Landing Page HTML Extraction

新增一个安全的 HTML fetch 能力。

建议后端/Tauri 命令：

```text
fetch_public_html(url, maxBytes=2MB, timeout=15s)
```

限制：

- 只允许 http/https。
- 拒绝 blocklist host。
- 不执行 JS。
- 限制大小、超时、跳转次数。
- 只解析 HTML 文本。

提取规则：

- `<a href="...pdf...">`
- `<meta name="citation_pdf_url" content="...">`
- `<meta name="dc.identifier" ...>` 中可能的 PDF
- JSON-LD 中的 `contentUrl` / `url`
- OSF/SSRN/PsyArXiv 常见 download 链接

候选链接全部转绝对 URL 后走 `%PDF` 校验。

### 5.7 Optional Web Discovery

Lumen 当前没有 Claude Code 那种通用 WebSearch。

可以分两步做：

第一步，不接外部搜索 API：

- DOI based resolvers
- OpenAlex detail
- Semantic Scholar detail
- Unpaywall
- landing page extraction

第二步，再加可配置 WebSearch provider：

```ts
interface WebSearchProvider {
  search(query: string, limit: number): Promise<WebSearchResult[]>
}
```

查询模板：

```text
"{exact title}" PDF
"{exact title}" DOI
"{exact title}" author PDF
site:osf.io "{exact title}"
site:psyarxiv.com "{exact title}"
site:ssrn.com "{exact title}"
```

WebSearch 结果只作为 landing candidates，不能直接信任。

### 5.8 Blocklist

工具层必须有 blocklist：

```text
sci-hub
libgen
library genesis
z-lib
zlibrary
annas-archive
```

如果 URL / host / title 命中这些来源：

- 标记 attempt 为 `blocked`
- 不打开
- 不下载
- 不把链接展示为建议下载来源

### 5.9 接入 Paper Preview

`previewSearchResultPaper()` 改成：

```text
pdfUrl = directPdfUrl(paper)
if !pdfUrl:
  resolution = await resolveOpenPdf(paper)
  pdfUrl = resolution.pdfUrl

if pdfUrl:
  fetchPdfBytes(pdfUrl)
  extractPdfText
  evidenceLevel=pdf_text_preview
else:
  evidenceLevel=abstract_only/metadata_only
  message includes resolver attempts summary
```

### 5.10 接入 Evidence Notes

`PaperEvidenceNote.warning` 应包含：

- 尝试了哪些来源
- 找到了哪些 landing page
- 为什么没有下载
- 是否因为 paywall / no PDF / blocked source / verification failed

这样用户看到 `abstract_only` 时，不会觉得系统“没意识”，而是知道系统尝试过哪些合法路径。

## 6. 验收标准

- 对只有 DOI、没有 direct PDF 的论文，系统会先尝试 Unpaywall / OpenAlex detail / Semantic Scholar detail。
- 对 OSF、SSRN、PsyArXiv、arXiv landing page，系统能从 HTML 或 metadata 中提取 PDF link 并校验。
- 对 ScienceDirect / publisher paywall 页面，系统不绕过权限；如果没有公开 PDF，明确降级。
- 对 Sci-Hub / LibGen / Anna's Archive 等来源，系统 block，不打开、不下载。
- “Aha! moments correspond to metacognitive prediction errors” 这类论文，如果存在 SSRN/OSF/预印本公开 PDF，应能解析到 direct PDF 并进入 `pdf_text_preview`。
- 如果最终仍然 `abstract_only`，回答中要说明 resolver attempts，而不是只说“没有获取到 PDF”。
- 所有 PDF 仍然只进临时缓存，不导入文献库。
