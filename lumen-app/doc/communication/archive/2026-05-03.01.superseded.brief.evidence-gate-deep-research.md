## 1. 当前判断

上一轮已经实现了重要底座：

- `research_artifacts`
- `currentPaper`
- `search_results` 持久化与恢复
- direct PDF URL / landing page 拆分
- paper preview 临时 PDF 读取与缓存

但用户实测后发现：Lumen 仍然只能回答浅层问题。

根因不是没有 PDF 读取能力，而是：

```text
搜索链路没有接入论文原文 evidence pipeline。
```

现在的行为仍然像这样：

```text
academic_search -> metadata/abstract search results -> synthesize answer
```

真正研究型问题应该是：

```text
search -> select papers -> fetch/read temporary PDF -> per-paper evidence notes -> synthesis
```

## 2. P0 Finding: academic_search 对分析型问题仍停在 metadata/abstract

位置：

- `src/agent/runtime.ts:298-353`
- `src/agent/prompts.ts:143-170`

现状：

- `academic_search` 分支执行 `runAcademicSearches()`。
- 然后执行 `reflectOnSearchResults()`。
- 最后直接调用 `synthesizeAnswer()`。
- `synthesizeAnswer()` 只接收 `SearchBatch[]`。
- `buildSynthesisUserPrompt()` 要求“基于搜索结果回答”，搜索结果主要是标题、作者、摘要、链接、引用数。
- 这个分支完全没有调用 `previewSearchResultPaper()`。

影响：

- 用户说“帮我找几篇论文并解释它们的方法/结论/贡献/局限”，系统会搜索，但不会主动读开放 PDF。
- 回答会停留在摘要层，像“文献推荐列表”，不是研究分析。
- 用户必须二次追问“第 N 篇讲什么”才触发 `paper_preview`。

## 3. P0 Finding: deep_research 仍是硬编码降级

位置：

- `src/agent/runtime.ts:149-152`
- `src/agent/prompts.ts:45`

现状：

`deep_research` 分支直接返回：

```text
“多篇开放 PDF 深读并综合对比”的 deep research 链路还没有完整接好。
```

影响：

- “深入对比这几篇”
- “深读这些论文”
- “帮我综合它们的方法和结论”

这些需求都无法进入多篇 PDF 读取和综合链路。

## 4. P1 Finding: planner 缺少 Evidence Gate 信号

位置：

- `src/agent/types.ts`
- `src/agent/prompts.ts:38-55`

现状：

planner 只输出 `intent`，没有输出“回答所需证据层级”。

建议新增：

```ts
export type EvidenceRequirement =
  | 'metadata_ok'
  | 'abstract_ok'
  | 'single_pdf_required'
  | 'multi_pdf_required'
```

扩展 `SearchPlan`：

```ts
interface SearchPlan {
  intent: ResearchIntent
  shouldSearch: boolean
  queries: string[]
  evidenceRequirement?: EvidenceRequirement
  targetPaperCount?: number
}
```

规则：

- 作者、年份、DOI、链接、期刊：`metadata_ok`
- 摘要层概览、推荐列表：`abstract_ok`
- 单篇论文的方法、实验、结论、贡献、局限、理论：`single_pdf_required`
- 多篇论文对比、综述、深读、综合方法：`multi_pdf_required`

## 5. 推荐实现方案

### 5.1 新增 Evidence Gate

建议新增工具函数：

```ts
function requiresPrimarySource(userText: string, plan: SearchPlan): boolean
```

判断条件包括：

```text
方法、实验、结果、结论、贡献、局限、理论、定义、如何证明、怎么做、为什么重要、对比、综合、深读、详细分析
```

如果 planner 没有稳定输出 `evidenceRequirement`，runtime 也应该用这个 deterministic gate 兜底。

### 5.2 academic_search 自动进入 paper preview topK

当满足：

```ts
plan.intent === 'academic_search'
&& plan.evidenceRequirement in ['single_pdf_required', 'multi_pdf_required']
```

或 deterministic gate 判断需要原文证据时，流程改为：

```text
runAcademicSearches
-> reflectOnSearchResults
-> mergeSearchBatches
-> select topK papers with direct PDF
-> previewSearchResultPaper for each
-> build per-paper evidence notes
-> synthesizeEvidenceAnswer
```

默认策略：

- topK 默认 3。
- 用户明确说“几篇/5篇/这些论文”时最多 5。
- 只临时读取开放 PDF，不导入文献库。
- 没有 direct PDF 的论文可以保留 metadata/abstract，但必须标注 evidence level。

### 5.3 deep_research 真正执行多篇读取

`deep_research` 不应再硬编码降级。

建议流程：

```text
resolve selected papers from currentPaper / lastSearchResults
or run academic_search if no selected papers
-> select topK
-> preview PDF text for each
-> create per-paper analysis notes
-> cross-paper synthesis
-> persist deep_research_report artifact
```

如果没有足够 direct PDF：

```text
明确说明哪些论文读到了 PDF，哪些只能基于摘要/元信息。
```

不能直接说“链路没接好”。

### 5.4 新增 per-paper evidence notes

建议新增类型：

```ts
interface PaperEvidenceNote {
  paper: SearchResult
  evidenceLevel: 'metadata_only' | 'abstract_only' | 'pdf_text_preview'
  text: string
  cacheHit: boolean
  pdfCacheHit: boolean
  warning?: string
}
```

可以先直接复用 `PaperPreviewData`，但 synthesizer prompt 中需要明确每篇的 evidence level。

### 5.5 持久化新 artifact

搜索 + 读取后建议写入：

```text
paper_preview
deep_research_report
```

最小实现可以先只写 `deep_research_report`：

```json
{
  "query": "...",
  "papers": [
    {
      "title": "...",
      "evidenceLevel": "pdf_text_preview",
      "cacheHit": false
    }
  ],
  "createdAt": "..."
}
```

### 5.6 模型路由建议

- planner/search query：flash。
- PDF evidence synthesis / cross-paper synthesis：pro。
- 不要用 cheap model 做深读综合。

## 6. Prompt 改造要求

`PLANNER_SYSTEM_PROMPT` 需要明确：

- “找论文并解释/总结/分析/对比”不是纯 `academic_search`。
- 这类问题应设置 `evidenceRequirement=multi_pdf_required` 或至少 `single_pdf_required`。
- 用户不必显式说“读 PDF”；只要问题要求论文内容，就需要一手材料。

`buildSynthesisUserPrompt()` 也需要拆分：

- search-only synthesis：只做推荐、元信息说明。
- evidence synthesis：基于 PDF 临时文本和 per-paper note 回答。

不要继续让同一个 `buildSynthesisUserPrompt()` 承担所有场景。

## 7. 验收标准

- 用户问“帮我搜索几篇 aha moment 论文，并解释它们的方法和结论”，系统会搜索后自动临时读取 top 3 direct PDF，再综合回答。
- 用户问“深入对比第 1、2、3 篇”，系统会读取这几篇的开放 PDF 或明确标注哪几篇无法读取。
- 用户问“推荐几篇相关论文”，可以只返回搜索结果，不强制读 PDF。
- 用户问“这篇的 DOI 是什么”，只走 metadata，不读 PDF。
- 用户问“这篇怎么定义 aha moment”，如果有 `currentPaper`，走 paper preview。
- 回答必须标注 evidence level：PDF 临时文本 / abstract / metadata。
- 没有 direct PDF 时，不编造全文细节，只做降级说明。
- 所有 PDF 读取仍然只进入临时缓存，不导入文献库。
