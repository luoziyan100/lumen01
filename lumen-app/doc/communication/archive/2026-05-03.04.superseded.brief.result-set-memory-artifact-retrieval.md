## 1. 用户复现

用户流程：

```text
1. 搜索“上周 AI 领域论文”
2. Lumen 返回 totalAvailable 约 1428，并列出 10 篇
3. 中间聊了机器学习分类等话题
4. 用户说：“那你筛选出来的 10 篇论文里面的前 5 篇，做一个研究报告”
5. Lumen 研究了另外 5 篇机器学习/医学分类论文，不是刚才那 10 篇
6. 用户追问链接，Lumen 又说之前没有保存 arXiv ID 或 URL
```

判断：

这不是单纯模型问题。核心是 Agent state / artifact retrieval 仍然不完整。

Lumen 现在有聊天文本，也有单个 `lastSearchResults`，但没有稳定的“结果集对象”。一旦中间发生新的搜索、planner 误判要重新搜索，或者页面恢复只取最新 artifact，用户说的“刚才那 10 篇 / 前 5 篇”就无法可靠绑定到原来的结果集。

## 3. P0 Finding: deep_research 先搜索再解析引用

位置：

- `src/agent/runtime.ts:280-298`

现状：

```ts
let searchResults = input.context.lastSearchResults ?? []

if ((plan.shouldSearch && plan.queries.length > 0) || (searchResults.length === 0 && plan.queries.length > 0)) {
  const search = await runSearchPipeline(input, trace, plan)
  searchResults = search.searchResults
}

const resolved = resolvePaperReferences(plan, input.userText, {
  currentPaper: input.context.currentPaper,
  lastSearchResults: searchResults,
}, limit)
```

问题：

用户说“你筛选出来的 10 篇里面前 5 篇”时，应优先绑定上一轮结果集。但现在只要 planner 输出 `shouldSearch=true`，runtime 会先重新搜索，再把新结果传给 `resolvePaperReferences()`。这正好解释了为什么它研究出一批“机器学习分类/医学分类”论文。

建议：

```text
deep_research:
  1. 先判断用户是否引用现有结果集
     - 前 5 篇
     - 刚才那 10 篇
     - 你筛选出来的论文
     - 上一轮结果
     - R1 / S1 / 结果集 1
  2. 如果能解析到现有结果集，禁止重新搜索
  3. 只有用户明确要求“重新搜/再搜/换一批/最新再查一次”，或没有可解析结果集时，才 runSearchPipeline
```

## 4. P0 Finding: `lastSearchResults` 是单个可变指针

位置：

- `src/pages/ResearchPage.tsx:318-325`
- `src/pages/ResearchPage.tsx:333-340`
- `src/agent/types.ts:48-57`

现状：

```ts
context: {
  lastSearchResults,
  currentPaper,
}
```

问题：

`lastSearchResults` 只能代表“最近一次搜索”。它无法表达：

- 上一轮 feed 返回的 10 篇。
- 更早一轮搜索结果。
- 用户当前正在引用的是哪一组结果。
- “前五篇”应该对应哪个结果集。

建议新增稳定结果集模型：

```ts
interface SearchResultSet {
  id: string
  label: string          // 例如 R1 / 2026-05-03 上周 AI feed
  noteId?: string
  query: string
  plan: SearchPlan
  mode?: SearchMode
  totalAvailable?: number
  fetched?: number
  categories?: string[]
  fromDate?: string
  untilDate?: string
  results: SearchResult[]
  createdAt: string
}
```

Agent context 应从单个 `lastSearchResults` 升级为：

```ts
interface AgentInputContext {
  activeSearchResultSetId?: string
  recentSearchResultSets?: SearchResultSet[]
  lastSearchResults?: SearchResult[] // 可保留兼容，但不再作为唯一状态
}
```

## 5. P0 Finding: 页面恢复只读最新一个 search artifact

位置：

- `src/pages/ResearchPage.tsx:139-152`

现状：

```ts
listResearchArtifacts(projectId, 'search_results', 1)
setLastSearchResults(restoredSearchResults(searchArtifacts[0]))
```

问题：

即使 artifacts 正常保存，页面恢复也只取最新一个 `search_results`。如果用户先搜索 AI feed，再聊别的话题导致另一次搜索，旧的 10 篇就从 agent context 里消失。

建议：

- 恢复最近 5-10 个 search result sets。
- 保留 `activeSearchResultSetId`。
- 对每个 result set 保留完整 `SearchResult[]` 和可读 label。
- Planner prompt 中提供最近结果集摘要，而不是只提供最新 12 条 paper。

## 7. Result Reference Resolver

新增 resolver，不要只靠模型记忆。

建议能力：

```ts
resolveResultSetReference(userText, context):
  - “刚才/上一轮/你筛选出来的/那 10 篇” -> activeSearchResultSet
  - “前 5 篇 / 第 1-5 篇 / 前五篇” -> activeSearchResultSet.results.slice(0, 5)
  - “第 2 篇” -> activeSearchResultSet.results[1]
  - “R1 前 5 篇” -> resultSet(id=R1).results.slice(0, 5)
  - 如果有多个候选且歧义高，先 clarify，不要擅自重搜
```

注意：

`resolvePaperReferences()` 当前只看 `lastSearchResults`，要扩展到 `recentSearchResultSets`。

## 8. Planner / Runtime 规则

Prompt 要加规则，但不能只靠 prompt。

Planner rule：

```text
如果用户引用“刚才那批 / 你筛出来的 / 前几篇 / 上面这些论文”，不要设置 shouldSearch=true，除非用户明确说重新搜索。
```

Runtime deterministic guard：

```ts
const existingRef = resolveResultSetReference(userText, context)
if (existingRef.ok) {
  plan = { ...plan, shouldSearch: false }
  selectedPapers = existingRef.papers
} else if (shouldSearch) {
  search...
}
```

这个 guard 是必须的，因为 planner 仍可能被中间话题带偏。

## 9. UI / Response 行为

搜索结果回复建议明确标识结果集：

```text
结果集 R1：上周 arXiv AI feed
时间：2026-04-27 至 2026-05-03
总数：1428
本次展示：10 / 已拉取 50
```

每篇显示稳定编号：

```text
R1-1. Title ...
R1-2. Title ...
```

后续用户说“前五篇”，系统应知道是 `R1-1` 到 `R1-5`。

## 10. 验收用例

必须通过这些手工测试：

1. 搜索“上周 AI 领域论文”，返回 R1 和 10 篇。
2. 问“机器学习有哪些分类”，不应覆盖 R1。
3. 问“那你筛选出来的 10 篇论文里面的前 5 篇，做一个研究报告”，必须使用 R1-1 到 R1-5。
4. 问“把它们链接拿出来”，必须输出 R1-1 到 R1-5 的 `source_url` 和可用 PDF URL。
5. 刷新页面/切换研究历史再回来，R1 仍可被引用。
6. 如果用户说“重新搜一批上周 AI 论文”，才创建 R2。
7. 如果存在 R1/R2 且用户只说“前 5 篇”，系统应优先 active result set；歧义时询问，不要搜索。
