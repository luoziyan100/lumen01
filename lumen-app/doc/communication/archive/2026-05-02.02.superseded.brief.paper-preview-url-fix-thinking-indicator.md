## 1. PR 目标

这次是一个小而关键的修复 PR，不要重写整个 Agent 流程。

需要修两类问题：

- Paper Preview 已经有临时下载和缓存链路，但搜索结果里的 `open_access_url` 混入了 landing page，导致系统把网页当 PDF 下载，出现“响应内容不像 PDF 文件”。
- 研究页加载状态现在显示“正在规划回答...”，用户希望改成英文 `Thinking...`，并且 `...` 有动态变化效果。

## 2. Review Findings

### P1: OpenAlex 把开放获取页面当成 PDF URL

位置：

- `src-tauri/src/commands/search.rs:690-712`
- `vite.config.ts:383-386`

问题：

当前实现把这些字段都塞进 `open_access_url`：

- `open_access.oa_url`
- `best_oa_location.pdf_url`
- `best_oa_location.landing_page_url`

OpenAlex 的 `oa_url` 和 `landing_page_url` 经常是 OSF、期刊、OpenAlex、publisher 页面，不一定是 PDF。后续 `paper_preview` 会直接拿 `open_access_url` 调 `fetch_open_pdf`，所以很容易下载到 HTML 页面。

### P1: UI 把所有 open access URL 都显示成 `[PDF]`

位置：

- `src/services/search.ts:67`

问题：

只要 `open_access_url` 存在，搜索结果就显示 `[PDF]`。但这个 URL 可能只是开放页面，不是可读取 PDF。

### P2: PDF 校验不能靠 URL 后缀兜底通过

位置：

- `src-tauri/src/commands/files.rs:85-96`
- `vite.config.ts:601-613`

问题：

当前校验逻辑只要 URL 包含 `.pdf`，即使响应体不是 `%PDF`，也可能被接受并缓存。这样会把 HTML 错误页、跳转页或登录页缓存成 PDF，后续 pdf.js 再失败。

## 3. 推荐实现方案

### 3.1 拆分 URL 字段语义

推荐在 `SearchResult` 中拆出明确字段：

```ts
interface SearchResult {
  open_access_pdf_url: string | null
  open_access_landing_url: string | null
  source_url: string
}
```

如果为了兼容暂时保留 `open_access_url`，也必须重新定义它：

```text
open_access_url 只能表示 direct PDF URL，不允许放 landing page。
```

但长期更推荐显式拆分，避免后面继续踩坑。

Rust、前端、dev fallback 需要同步更新：

- `src-tauri/src/commands/search.rs`
- `src/services/search.ts`
- `src/services/paper-preview.ts`
- `src/agent/prompts.ts`
- `src/agent/runtime.ts`
- `src/agent/tools.ts`
- `vite.config.ts`

### 3.2 OpenAlex 映射规则

OpenAlex 中只把 direct PDF 候选写入 PDF 字段：

```text
open_access_pdf_url =
  primary_location.pdf_url
  ?? best_oa_location.pdf_url
  ?? null
```

landing page 单独保存：

```text
open_access_landing_url =
  open_access.oa_url
  ?? best_oa_location.landing_page_url
  ?? primary_location.landing_page_url
  ?? null
```

`source_url` 仍然作为用户可点击来源：

```text
source_url =
  primary_location.landing_page_url
  ?? open_access.oa_url
  ?? OpenAlex id
```

注意：不要把 `oa_url` 当成 PDF，除非它经过后续 resolver 明确证明返回 `%PDF`。本 PR 不需要实现复杂 resolver。

### 3.3 其他数据源映射规则

Semantic Scholar：

- `openAccessPdf.url` 可以进入 `open_access_pdf_url`。
- `paper.url` 可以作为 `source_url` 或 landing URL。

arXiv：

- XML 中 `title="pdf"` 的 link 可以进入 `open_access_pdf_url`。
- abstract entry URL 可以作为 `source_url`。

Crossref：

- 当前没有稳定 PDF 字段，默认 `open_access_pdf_url = null`。
- DOI/URL 只作为 `source_url` 或 landing URL。

### 3.4 Paper Preview 只读取 direct PDF

`src/services/paper-preview.ts` 应改为：

- 只有 `paper.open_access_pdf_url` 存在时才调用 `fetchPdfBytes`。
- 没有 direct PDF 时，不要拿 landing page 去试下载。
- 降级提示应从“开放 PDF 临时读取失败”变成更准确的“没有可直接读取的开放 PDF，只能基于摘要和元信息回答”。
- `formatPaperDetailContext` 中要分别展示“开放 PDF”和“开放页面/来源链接”。

### 3.5 UI 链接文案

`formatSearchResults` 中链接展示建议：

```text
[PDF] 只显示 direct PDF
[开放页面] 显示 open access landing page
[来源] 显示 source_url
```

不要再把 landing page 显示成 `[PDF]`。

### 3.6 PDF 校验必须看响应体

Tauri 和 Vite dev proxy 都要调整：

- 缓存前必须确认响应 bytes 的前若干字节里存在 `%PDF` magic header。
- `Content-Type: application/pdf` 和 URL `.pdf` 只能作为辅助信息，不能作为最终通过条件。
- 非 PDF 响应不能写入缓存。

建议逻辑：

```text
is_pdf = bytes first 1024 bytes contains "%PDF"
if !is_pdf => reject and do not cache
```

## 4. Thinking 动态状态

位置：

- `src/pages/ResearchPage.tsx:594`

当前：

```tsx
<span className="t-body-sm">正在规划回答...</span>
```

目标：

```text
Thinking
Thinking.
Thinking..
Thinking...
```

循环动态变化，间隔建议 350-500ms。

实现建议：

- 保留现有 spinner。
- 新增一个很小的 `ThinkingStatus` 子组件，内部用 `useEffect` + `setInterval` 更新 dots。
- 不需要为了这个引入额外依赖。
- 组件卸载时清理 interval。

可接受实现示例：

```tsx
function ThinkingStatus() {
  const [dots, setDots] = useState('')

  useEffect(() => {
    const id = window.setInterval(() => {
      setDots((current) => (current.length >= 3 ? '' : `${current}.`))
    }, 400)
    return () => window.clearInterval(id)
  }, [])

  return <span className="t-body-sm">Thinking{dots}</span>
}
```

## 5. 验收标准

- 搜索结果里的 `[PDF]` 只出现在 direct PDF URL 存在时。
- OpenAlex landing page 不再进入 Paper Preview 下载链路。
- 对只有摘要和 landing page 的论文，Agent 应明确说明只能基于摘要和元信息回答，而不是报“PDF 响应不像 PDF”。
- 对 Semantic Scholar/arXiv 这类 direct PDF，Paper Preview 仍可临时下载、抽取文本、命中缓存。
- 非 PDF 响应不会写入 Tauri 或 dev proxy 的 PDF 缓存。
- `ResearchPage` loading 状态显示动态 `Thinking...`，dots 会循环变化。
- 不改变“只有用户明确要求保存/导入时才进入文献库”的边界。
