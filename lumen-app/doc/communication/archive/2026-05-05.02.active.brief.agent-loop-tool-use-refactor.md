## 0. Why this refactor exists

当前 Research Agent 有一个根本性的设计缺陷：**用正则做 LLM 擅长的事**。

具体的 bug：用户搜索论文后说"那你把这5篇做一个研究报告吧"，系统回复"没有可用于深度研究的搜索结果"。原因是 `hasStrongResultSetAnchor` 正则要求"篇"后面必须跟"论文/文献"，"这5篇。"（句号结尾）就匹配失败了。

但这个 bug 不是根本问题——修了这个正则，下次用户说"把刚才那批做个报告"又挂了。正则永远覆盖不完自然语言。

当前 4543 行的 agent 代码本质上是一个正则驱动的管道：

```
正则门禁 (hasStrongResultSetAnchor)
→ 正则引用消解 (reference-resolver.ts)
→ 正则快速路由 (deterministicExternalSearchPlan)
→ LLM JSON Planner (只输出意图，不能调工具)
→ 900 行 if-else 分发 (runtime.ts)
→ 单次执行
```

真正的 Agent（Manus, Claude, ChatGPT）用的是 **Agent Loop + Tool Use**：

```
while not done:
  LLM 看到完整对话（含之前的搜索结果）
  LLM 决定：调工具 OR 直接回复
  if 调工具 → 执行 → 结果追加到对话 → 继续循环
  if 回复 → 结束
```

区别：
- LLM 天然理解"这5篇"指的是什么，因为它看到了完整对话
- 不需要正则解析引用
- 不需要外部 state 管理（对话历史就是 state）
- 不需要 900 行 if-else

**目标：用 Agent Loop + Tool Use 替代当前的正则管道。**

## 2. Target architecture

### 2.1 核心：Agent Loop

```typescript
// 新的 src/agent/loop.ts — 这是整个 agent 的核心，替代 runtime.ts 的 953 行
async function runAgentLoop(input: AgentLoopInput): Promise<AgentLoopResult> {
  const messages: AgentMessage[] = [
    { role: 'system', content: buildSystemPrompt(input.context) },
    ...input.conversationHistory,
    { role: 'user', content: input.userText },
  ]

  const MAX_STEPS = 10
  const newMessages: AgentMessage[] = []

  for (let step = 0; step < MAX_STEPS; step++) {
    const response = await callWithTools(messages, RESEARCH_TOOLS, input.signal)
    newMessages.push(response.message)
    messages.push(response.message)

    if (!response.toolCalls?.length) {
      return {
        reply: response.text,
        newMessages,
      }
    }

    for (const toolCall of response.toolCalls) {
      const result = await executeResearchTool(toolCall, input.signal)
      const resultMessage: AgentMessage = {
        role: 'tool_result',
        toolCallId: toolCall.id,
        content: JSON.stringify(result),
      }
      newMessages.push(resultMessage)
      messages.push(resultMessage)
    }
  }

  return {
    reply: '研究步骤过多，请缩小问题范围。',
    newMessages,
  }
}
```

### 3.2 CREATE `src/agent/adapters/claude.ts`

实现 `ClaudeAdapter`，调用 Anthropic Messages API with tools。

必须做的事：
- 把 `AgentMessage[]` 转换为 Anthropic messages 格式
- 把 `ToolDefinition[]` 转换为 Anthropic tools 格式
- 把 `role: 'tool_result'` 消息转换为 Anthropic 的 `tool_result` content block（放在 user 消息中，带 `tool_use_id`）
- 解析 response 中的 `tool_use` content block，提取 `id`, `name`, `input`
- 解析 response 中的 `text` content block
- 如果 response 包含 tool_use，设 `toolCalls`；否则只设 `text`
- 使用 `anthropic-dangerous-direct-browser-access: true` header（因为是浏览器端调用）

DO NOT:
- 不要用 Anthropic SDK，直接用 fetch（与现有 `ai.ts` 的 `callAnthropic` 保持一致）
- 不要硬编码模型名，从配置读取
- 不要忽略 `signal` 参数

Anthropic tool calling 请求格式（这是真实格式，不要自己猜）：

```json
{
  "model": "claude-sonnet-4-20250514",
  "max_tokens": 4096,
  "system": "...",
  "tools": [
    {
      "name": "academic_search",
      "description": "...",
      "input_schema": {
        "type": "object",
        "properties": { ... },
        "required": [...]
      }
    }
  ],
  "messages": [
    {"role": "user", "content": "搜索LLM论文"},
    {"role": "assistant", "content": [
      {"type": "tool_use", "id": "toolu_xxx", "name": "academic_search", "input": {"queries":["LLM"]}}
    ]},
    {"role": "user", "content": [
      {"type": "tool_result", "tool_use_id": "toolu_xxx", "content": "{...}"}
    ]},
    {"role": "assistant", "content": "找到了以下论文..."}
  ]
}
```

关键细节：
- Anthropic 的 `tool_result` 放在 **user** 消息里，不是单独的 role
- 一个 user 消息可以包含多个 `tool_result` content block（对应多个并行 tool call）
- `tool_use` 在 assistant 消息中，可以和 `text` content block 共存
- `input_schema` 不是 `parameters`——Anthropic 用 `input_schema`

验收标准：
- [ ] 构造一个包含 tool_use → tool_result → text 的三轮对话，验证消息格式转换正确
- [ ] tool_result 消息正确放在 user role 下，带 tool_use_id
- [ ] 解析 response 时正确区分 text 和 tool_use content block

### 3.3 CREATE `src/agent/adapters/openai.ts`

实现 `OpenAIAdapter`，调用 OpenAI Chat Completions API with tools。

OpenAI tool calling 请求格式：

```json
{
  "model": "gpt-5.5",
  "messages": [...],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "academic_search",
        "description": "...",
        "parameters": { ... }
      }
    }
  ]
}
```

OpenAI response 格式：

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_xxx",
          "type": "function",
          "function": {
            "name": "academic_search",
            "arguments": "{\"queries\":[\"LLM\"]}"
          }
        }
      ]
    },
    "finish_reason": "tool_calls"
  }]
}
```

关键细节：
- OpenAI 用 `"type": "function"` 包装工具定义
- response 中的 `arguments` 是 **JSON string**，不是 object，需要 `JSON.parse`
- tool result 消息用 `role: "tool"`（不是 "user"），带 `tool_call_id`
- `finish_reason === "tool_calls"` 表示模型在调工具，不是在回复

DO NOT:
- 不要把 OpenAI 的 tool_result 放在 user 消息里（那是 Anthropic 的格式）
- 不要忘记 parse `arguments` string

也必须处理 `openai-codex` provider。对于 openai-codex，tool calling 目前可能不支持。如果不支持，fallback 到 ReAct 模式（3.4）。具体判断方法：尝试调用，如果返回错误则 fallback。

验收标准：
- [ ] 消息格式转换正确（user, assistant, tool, system）
- [ ] tool_calls response 中的 arguments 被正确 JSON.parse
- [ ] tool result 使用 `role: "tool"` + `tool_call_id`

### 3.4 CREATE `src/agent/adapters/react-fallback.ts`

给 DeepSeek 和 custom provider 用。这些 provider 可能不支持原生 tool calling。

方案：把工具定义注入 system prompt，让模型用特定格式输出工具调用，然后解析。

注入的格式（追加到 system prompt 末尾）：

```
## 可用工具

你可以调用以下工具。要调用工具，用以下 JSON 格式回复，不要包含其他文字：

<tool_call>
{"name": "工具名", "arguments": {...}}
</tool_call>

工具列表：
- academic_search: 搜索外部学术论文数据库...
  参数：queries (必填), time_range, sort, mode, limit
- read_papers: 临时读取论文内容...
  参数：papers (必填, 最多5篇)
- search_local_library: 搜索用户本地文献库...
  参数：query (必填)

如果你不需要调用工具，直接用普通文本回复用户。
```

解析逻辑：
1. 检查 response 中是否包含 `<tool_call>...</tool_call>`
2. 如果有，提取 JSON，构造 `ToolCall`
3. 如果没有，整个 response 就是 text

DO NOT:
- 不要假设所有 provider 都能完美遵循格式。如果 JSON 解析失败，把整个 response 当作 text 返回（graceful fallback）
- 不要用复杂的 XML parser，用简单的正则提取 `<tool_call>` 和 `</tool_call>` 之间的内容

验收标准：
- [ ] 工具定义被正确注入 system prompt
- [ ] 能从 `<tool_call>{...}</tool_call>` 格式中提取工具调用
- [ ] 不包含 `<tool_call>` 的普通回复被正确处理为 text
- [ ] 格式错误时 graceful fallback 为 text

### 3.5 CREATE `src/agent/adapters/adapter-factory.ts`

```typescript
import type { LLMAdapter } from './types'
import { ClaudeAdapter } from './claude'
import { OpenAIAdapter } from './openai'
import { ReActFallbackAdapter } from './react-fallback'

export async function createAdapter(): Promise<LLMAdapter> {
  const config = await getAiConfig()
  if (!config) throw new Error('请先在设置中配置 AI 模型')

  switch (config.provider) {
    case 'anthropic':
      return new ClaudeAdapter(config)
    case 'openai':
      return new OpenAIAdapter(config)
    case 'openai-codex':
      return new OpenAIAdapter(config)  // 如果不支持 tool calling，在 adapter 内部 fallback
    case 'deepseek':
      return new ReActFallbackAdapter(config)
    case 'custom':
      return new ReActFallbackAdapter(config)
    default:
      return new ReActFallbackAdapter(config)
  }
}
```

DO NOT:

## 5. DO NOT list (anti-shortcut measures)

这一节列出 Codex 可能走的捷径，以及为什么不能走。

### 5.1 不要把旧的正则管道"包装"成新架构

错误做法：把 `runtime.ts` 重命名为 `loop.ts`，在外面套一层 while 循环，内部逻辑不变。

判断标准：如果新的 `loop.ts` 超过 150 行，或者包含任何正则表达式，就是在做这件事。

### 5.2 不要用"planner + executor"模式模拟 tool calling

错误做法：保留现有的 LLM planner（outputting JSON intent），然后在"executor"里调用工具，把结果再传回给另一个 LLM call。

这不是 Agent Loop。Agent Loop 的关键是 **同一个模型在同一个对话中既决策又综合**，不是两个模型分工。

### 5.3 不要跳过 adapter 层直接在 loop 里写 API 调用

错误做法：在 `loop.ts` 里直接 `fetch('https://api.anthropic.com/...')`。

必须通过 adapter 抽象层，因为 Lumen 支持多个 provider。

### 5.4 不要保留 R1/R2 作为程序化锚点

R1/R2 标签在旧架构中是正则解析的关键依赖。在新架构中，模型自己决定引用哪些论文，不需要编号系统。

模型在回复中可以自由使用任何编号方式（1/2/3 或序号或标题），但代码层面不应该有任何 R1/R2 相关逻辑。

### 5.5 不要在 system prompt 中嵌入搜索结果

错误做法：在每轮调用前把 `lastSearchResults` 塞进 system prompt。

搜索结果已经在对话历史里了（作为 `academic_search` 的 tool_result）。重复嵌入浪费 token 且容易不一致。

### 5.6 不要把 research-judgment.ts 拖进重构

`research-judgment.ts` 是独立的评测模块（618 行），有自己的逻辑。这次重构不动它。如果 research judgment 需要适配新架构，那是另一个 brief 的事。

在 Phase 2 中，如果用户输入触发了 research judgment，可以暂时走旧路径或者返回"评测功能正在升级中"。不要为了兼容 research judgment 而保留旧的 runtime.ts。

### 5.7 不要用"先重构后删除"拖延删除

Phase 2 的验收标准明确要求删除旧文件。不允许"Phase 3 再删除"。如果不删除，旧代码会继续被误引用。

### 5.8 不要偷偷保留 writeback

新架构中对话历史就是状态。如果你发现自己在写类似 `setLastSearchResults(result.searchResults)` 的代码，你在做错误的事。

### 5.9 不要只写 Claude adapter 然后说"其他 adapter 留给后续"

Phase 1 要求三个 adapter 都实现。DeepSeek 是 Lumen 用户最常用的 provider 之一，不能跳过。
